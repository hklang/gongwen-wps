# 公文写作工艺库

## 这是什么

一套机关公文的标准化生产方法。从原始素材到成品，按"六阶段 + 版本管理"两套机制走完。

## 怎么用

### 第一步：读通用规范

从 [机关公文通用写作规范.md](机关公文通用写作规范.md) 开始。先看"六阶段总流程图"和"通用规则"两节。

### 第二步：选子工艺

进入对应子文件夹，读该类型的生产工艺文档：

| 类型 | 位置 | 适用场景 |
|------|------|---------|
| 谈心谈话提纲 | [`谈心谈话/`](谈心谈话/) | 一对多/一对一的廉政提醒谈话 |
| 廉政谈话提纲 | [`廉政谈话/`](廉政谈话/) | 分管领导对下属的集体廉政谈话 |

### 第三步：翻工序手册

`writer/` 下编号文档（00-09），每个工序有详细操作手册：

## 版本管理（写作全程要用）

每写一轮就保存一版，**文件名带时间戳**。约定：

```
var/
├── 廉政谈话提纲(1)_原稿.md              ← 原始素材转过来的初版
├── 廉政谈话提纲_20260604_083053.md      ← 探测性修改前
├── 廉政谈话提纲_20260604_102324.md      ← 当前版
└── 廉政谈话提纲_20260604_102324.docx
```

原则：
- **每轮修改前**先备份一次（在 `var/` 里复制一份带时间戳的）
- **结构定型后**（一级标题敲定、子条目框架敲定）必须存一版
- **最终定稿后**保留 md + docx 两份
- 出问题随时 `Move-Item` 回 `var/` 里任意一版

## 探测性修改机制

新版本有时需要"试一下看效果"，**别直接覆盖**。约定：

- 在 md 里用 `<span>【试探性内容】</span>` 标记新增/修改部分
- 这种标记在 docx 输出时不影响排版，只在 md 里看得见
- 用户确认后去掉 `<span>【】</span>` 包裹，正式定型

## 配套工具

`tools/` 目录包含格式转换和排版工具：

| 工具 | 功能 | 文档 |
|------|------|------|
| `docx2md.py` | docx → md（保留格式层级） | `tools/文件转md方法.md` |
| `md2docx.py` | md → docx（公文排版零手动） | `tools/README.md` |

md 语法与 Word 效果的完整对照表见 `tools/README.md`，详细排版参数见 `tools/政府公文排版规范.md`。移植到新项目时复制整个 `tools/` 目录即可。

## 铁律（破一条就要重写）

1. **不出现"——"**——破折号打断节奏，docx 显示差
2. **不出现"。"、"、"`——句号是公文标配，顿号只用于并列
3. **不堆砌排比**——4 字对仗最多 3 处，全文不超 5 处
4. **不写未经核实的数字/人名/项目名**——核查阶段逐条回查原素材
5. **不脱离讲话人身份**——总经理写出来的话要像总经理，党委书记写出来的话要像党委书记
6. **法规引用首次全名 + 后续"《规定》"简称**——避免每次都读完整名
7. **探测性修改用 `<span【……】></span>` 标记**——定稿前 `grep span【` 必查清零
8. **凡涉及具体事实的句子必有出处**——出处不全=不合格

```
├── src2/                      ← 转换后的 md
└── var/                       ← 版本快照（每轮修改前备份）
```
