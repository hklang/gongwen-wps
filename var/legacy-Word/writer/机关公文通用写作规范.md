# 机关公文通用写作规范

把原始文件加工为机关公文成品的标准化方法。适用于述职报告、发言稿、汇报材料、谈心谈话提纲、廉政谈话提纲等各类机关公文。

## 七阶段总流程

```
┌───────────────────────────────────────────────────────────────────────┐
│                                                                       │
│  ① 准备 ─→ ② 构思 ─→ ③ 撰写 ─→ ④ 打磨 ─→ ⑤ 核查 ─→ ⑥ 输出        │
│    收转标    搭框架     写内容     统语言     验出处     出文件        │
│         ↑                                                            │
│         │  ⑦ 搜素与积累（贯穿全程，写前写中写后都要用）              │
│         │    [00-搜索与积累.md]                                       │
│         │                                                            │
│         └──────────────── 0 阶段：写前先做                            │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

每一阶段产出物：

| 阶段 | 关键产出 | 进入下一阶段的条件 |
|------|---------|-----------------|
| 0 搜索与积累 | search_results/ 模板库 + 拆解表 | 见过 5-10 篇同题材范文 |
| ① 准备 | src2/ + 素材清单 | 必用表述、业务数据已标出 |
| ② 构思 | 一级标题 + 板块引语 + 子条目占位 | 框架得到用户确认 |
| ③ 撰写 | md 草稿（含探测性标记） | 各板块内容齐全 |
| ④ 打磨 | 收紧、加黑、语序 | 多余内容砍光 |
| ⑤ 核查 | 引号/数据/人物全部有出处 | 全部回查通过 |
| ⑥ 输出 | docx 终稿 | Word 打开人工复核 |

## 阶段一：准备——收、转、标

### 收：要什么素材

不同文种需要的素材不同（见具体文种工艺文档的"素材清单"章节）。通用原则：四类必有输入——

| 必有输入 | 说明 |
|---------|------|
| 任务要求 | 谁布置的、要什么文本、给谁用、什么时间 |
| 对象材料 | 文本涉及的人/事/数据的原始记录 |
| 主体材料 | 署名者/讲话人的既往文稿 |
| 上级文件 | 相关政策、法规、领导讲话 |

### 转：统一格式

所有原始文件转为可检索的纯文本。转换原则：
- 保留格式层级（标题、加粗、缩进），否则无法判断原文语境
- 禁止纯文本提取（丢失格式信息，后续无法还原）
- **新格式都用 `tools/docx2md.py` 跑一遍**（按字体/字号/加粗识别标题层级）

### 标：标注素材

通读每份材料，标注后续要用的内容。四类材料各有通用挖法。

### 标：版本管理（准备阶段就要做）

在 `var/` 目录下存一份"原始素材转过来的初版"，文件名带 `(1)_原稿` 后缀：

```powershell
# 准备阶段第一次保存
Copy-Item "src2\廉政谈话提纲(1).md" "var\廉政谈话提纲(1)_原稿.md"
```

后续每轮修改前都要先复制当前版本到 `var/`，文件名带时间戳：

```powershell
$ts = Get-Date -Format "yyyyMMdd_HHmmss"
Copy-Item "廉政谈话提纲(2).md" "var\廉政谈话提纲_${ts}.md"
```

## 阶段二：构思——搭框架

### 框架确认后才能写内容

**框架阶段只输出骨架**（一级标题、板块引语占位、子条目占位）。**不要在搭框架时展开论述**——框架如果后续要改，先写的全废。

### 一级标题的设计

| 板块 | 功能 | 该讲什么 |
|------|------|---------|
| 第一板块 | 建立共识 | 为什么要重视（认识+危害） |
| 第二板块 | 暴露差距 | 我们哪里做得不够（具体风险） |
| 第三板块 | 指明方向 | 接下来怎么做（责任落实） |

**三层之间不能并列**。如果第一层和第二层可以互换位置，说明框架的递进关系没建立起来。

### 子结构密度

| 板块 | 子点数量 | 展开方式 |
|------|---------|---------|
| 第一板块 | 2-3 个 | 用经典追问结构（为谁→什么→怎么） |
| 第二板块 | 3-5 个 | 用权威框架的条目数决定 |
| 第三板块 | 2-3 个 | 每条标题前半句点问题+后半句指方向 |

### 一级标题公式（范式库）

| 范式 | 公式 | 适用场景 |
|------|------|---------|
| A 动宾+价值 | `动宾短语 + 价值升华` | 最稳，几乎所有场景 |
| B "X人"四件套 | `动词 + 做 Y 的"Z人"` | 任前集体谈话 |
| C 身体部位 | `把 X 扛在肩上/放在心上/抓在手上` | 有节奏感的讲话 |
| D "在X上下功夫" | `在 X 上下功夫，坚定不移 Y` | 大型会议 |
| E "必须"系列 | `一是必须… 二是必须… 三是必须…` | 警示教育 |

### 框架阶段就要做版本备份

```powershell
# 框架敲定后
$ts = Get-Date -Format "yyyyMMdd_HHmmss"
Copy-Item "廉政谈话提纲(2).md" "var\廉政谈话提纲_${ts}_框架定稿.md"
```

## 阶段三：撰写——写内容

### 撰写前的"探测性修改"机制

**任何修改都不直接覆盖**。在 md 里用 `<span【试探性内容】></span>` 标记新增/修改部分——外层 `<span>` 标签，内层中文方括号 `【】`：

- 在 IDE 看得见、方便确认
- 输出 docx 时不影响排版
- **确认后去掉 `<span【】></span>` 包裹**，正式定型

例：

```markdown
近年来集团发展势头良好，<span【今年是"十五五"开局之年，各项工作实现了良好起步】></span>，在座各位付出了大量心血。
```

**法规引用规范**：第一次出现用全名+书名号（如"《国有企业领导人员廉洁从业规定》"），后续用"《规定》"简称，**避免每次都读完整名**。中央法规（规定/条例/办法/准则）的出处比集团内部讲话更有分量，能引则引。

### 删除 `<span【】></span>` 的检查清单

定稿前必须逐个确认：

- [ ] 文件全文无 `<span` 残留（用 `grep` 搜索）
- [ ] 排版没有因标记损坏
- [ ] 句子通顺，**不要出现"`【`开头的句子**"  
- [ ] 法规引用统一：首次全名 + 后续简称

### 板块引语写法

每个一级标题下先写一句引语再展开子点。引语=定调+过渡：承认现状→指出差距→引出下文。**不写超过 80 字**。

### 子条目格式规则

- **A 范式**：`**一是…**正文` ——段内加粗前缀，回排 docx 时自动加黑
- **B 范式**：`**一是/二是/三是**` + 单独段落 ——节奏最稳
- **"一要"范式**：`**一要…二要…三要**` ——动词统一，节奏整齐

### 撰写阶段要做版本备份

```powershell
# 每一轮"填肉"后
$ts = Get-Date -Format "yyyyMMdd_HHmmss"
Copy-Item "廉政谈话提纲(2).md" "var\廉政谈话提纲_${ts}.md"
```

## 阶段四：打磨——统语言

### 三个动作

1. **砍**——多余的话、多余的例子、多余的修辞
2. **统一**——动词、句式、字数
3. **替换**——口语化、抽象、没力的词换成具体、生动、有力

### 检验方法

出声通读全文。读不顺→句子太长；像绕口令→句式重复。

### 标题打磨三件套

- **压缩**——长标题砍成 8 字
- **统一**——三条子条目动词/句式一致
- **替换**——把"老好人""打嘴炮"等口语换成"敢抓敢管""真管真严"

### 铁律检查

打磨完必查：

- [ ] 没有"——"（破折号）
- [ ] 没有半角标点
- [ ] 没有超过 3 处的 4 字对仗排比
- [ ] 每条子条目都有 `<span>【探测性内容】</span>` 标记（撰写阶段）；定稿后去掉

---

## 阶段五：核查——验出处

### 三必查

- 引号内文字在原文中找得到
- 数字和程度表述有出处，没有就删掉或笼统化
- 归纳和引述边界清晰，归纳不标注为"写了自己……"

### 出处核查清单

每一句涉及具体事实的句子都要回查：

| 句子涉及 | 回查 |
|---------|------|
| 项目名称 | `src/` 原始文件 |
| 部门名称 | 工作方案/会议文稿 |
| 数字（金额、比例、节点） | 经营分析会原稿 |
| 政策表述 | 上级文件原文 |
| 案例描述 | 通报文件 |

### 核查工具：表格化比对

把全文涉及事实的句子列成表，逐条标注"出处文件+段落"。

## 阶段六：输出——出文件

### 工具

使用 `tools/md2docx.py`。自动处理公文排版：大标题宋体二号加黑居中、一级标题黑体三号、子条目楷体三号加黑、正文仿宋三号、段内混排前缀加黑、署名日期右对齐。

### 命令

```powershell
C:\ProgramData\anaconda3\python.exe tools\md2docx.py "输入.md" "输出.docx"
```

### 输出前检查

- 关闭 Word（文件占用会导致生成失败）
- 确认 Python 路径（部分机器需完整路径，避免系统劫持）

### 输出后验证

用 Word 打开检查：标题层级、段内加黑、署名对齐。有问题回到 md 修改，重新生成。

### 最终版本备份

```powershell
$ts = Get-Date -Format "yyyyMMdd_HHmmss"
Copy-Item "廉政谈话提纲(2).md" "var\廉政谈话提纲_${ts}_定稿.md"
Copy-Item "廉政谈话提纲(2).docx" "var\廉政谈话提纲_${ts}_定稿.docx"
```

## 通用写作铁律

1. **不出现"——"**——破折号打断节奏，docx 显示差
2. **不写未经核实的数字/人名/项目名**——核查阶段逐条回查原素材
3. **不脱离讲话人身份**——总经理写出来的话要像总经理，党委书记写出来的话要像党委书记
4. **不堆砌排比**——4 字对仗最多 3 处，全文不超 5 处
5. **不写没出处的引号内容**——"……"里的话必须能在原素材中找到
6. **不空喊口号**——每一条要求都有可操作的落点
7. **法规引用首次用全名 + 后续用"《规定》"简称**——避免每段都读完整名称
8. **凡涉及具体风险/项目/部门/数字的句子，必有出处**——出处不全=不合格

## 表格规范

表格是公文数据呈现的重要形式，应遵循以下规则：

### 表头说明

每个表格上方须标注表号及说明，格式为 **表X  说明文字**（表号与说明之间空两格，不用冒号、不加粗）。例如：

```
表1  暖棚各作物种植面积
```

### md 源文件写法

1. 表头说明写在表格前一行，与表格之间不空行
2. 表格用 GFM 格式：首行表头、次行分隔行（`:---`）、后续数据行
3. **表格内禁止使用 `**` 加粗标记**——会被原样输出为 `**文字**`，不会渲染为加粗
4. 表头说明文字（"表X"行）在正文中按仿宋体输出，不加粗

正例：
```markdown
表1  暖棚各作物种植面积
| 作物 | 面积 |
|:-----|:----:|
| 西红柿 | 1500㎡ |
```

反例（表格内不可用 `**`）：
```markdown
| **项目** | **金额** |   ← 错误，**会原样显示
```

### 排版规则（tools/md2docx.py 自动处理）

| 规则 | 说明 |
|:----|:------|
| 禁止跨页断行 | 每行设 `cantSplit`，整行不跨页 |
| 表头跨页重复 | 首行设 `tblHeader`，跨页后自动重复 |
| 大表分页 | 8行以上表格前自动插入分页符，整表从新页开始 |
| 表头跟随 | 表头说明段落设 `keepNext`，不与表格分开 |
| 表头灰底 | 表头行浅灰底纹（D9D9D9）、加粗 |
| 对齐 | 单元格文字居中、垂直居中 |
| 行高 | 设最小行高（约0.8cm），防止文字挤在一起 |
