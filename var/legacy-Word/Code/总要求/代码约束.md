# 代码约束规范

## 一、文件大小限制

| 类型 | 限制 | 说明 |
|------|------|------|
| 单个源文件 | **200KB** | 超过则强制拆分 |
| 单个前端组件 | **150KB** | React/Vue 组件 |
| 配置文件 | **50KB** | JSON/YAML/TOML |
| 测试文件 | **200KB** | 包含测试代码 |

**拆分原则**：
- handler 文件超过 200KB → 按功能拆分为 `_handler1.rs`, `_handler2.rs`
- 大型结构体定义独立为 `models/` 子模块
- 前端组件超过 150KB → 拆分为子组件 + 父组件组合

## 二、代码行数限制

| 类型 | 限制 | 说明 |
|------|------|------|
| 单个函数 | **100行** | 超过则重构 |
| 单个结构体 impl 块 | **300行** | 超过则拆分 |
| 单个 Rust mod | **500行** | 包含所有子模块总行数 |
| 单个 Go handler | **200行** | 超过则拆分 |
| 单个 React 组件 | **300行** | 超过则拆分 |

## 三、命名规范

### Rust
```rust
// 模块名: snake_case
mod proxy_dispatcher;

// 结构体: PascalCase
struct ProxyConfig {}
struct L7FloodRequest {}

// 函数: snake_case
fn load_providers() {}

// 常量: SCREAMING_SNAKE_CASE
const MAX_RETRY_COUNT: u32 = 3;

// 枚举成员: PascalCase
enum AttackMode { Http, Flood, Slow }
```

### Go
```go
// 包名: 简短小写
package handlers

// 结构体: PascalCase
type ProxyConfig struct{}

// 函数: PascalCase (导出) / camelCase (内部)
func LoadProviders() {}
func parseRequest() {}

// 常量: PascalCase
const MaxRetryCount = 3
```

### 前端 (React/TypeScript)
```typescript
// 组件: PascalCase
function ProxyDashboard() {}

// 函数/变量: camelCase
const handleSubmit = () => {};

// 常量: SCREAMING_SNAKE_CASE
const API_BASE_URL = '';

// 文件名: kebab-case
// proxy-dashboard.tsx
// use-proxy-list.ts
```

## 四、注释要求

| 文件类型 | 头部注释 | 行内注释 |
|----------|----------|----------|
| Rust (.rs) | ✅ 必须 | 复杂逻辑加注 |

```rust

//! 作者: xxx | 日期: 2024-01-01

```

```go

// 作者: xxx | 日期: 2024-01-01
```

## 五、错误处理

### Rust
```rust
// ✅ 必须使用 thiserror/anyhow
fn load_config() -> Result<AppConfig, anyhow::Result> {
    // 使用 anyhow::Context 提供上下文
}

// ✅ 错误传播使用 ?
let cfg = AppConfig::load().context("加载配置失败")?;
```

### Go
```go
// ✅ 必须返回 error
func LoadConfig() (*Config, error) {
    // 使用 fmt.Errorf 提供上下文
    return nil, fmt.Errorf("load config: %w", err)
}
```

**禁止**:
- ❌ `unwrap()` 在生产代码中（测试可用）
- ❌ `panic!()` 在业务逻辑中
- ❌ 忽略 error 返回值 `_`

## 六、日志规范

### 日志级别使用
| 级别 | 使用场景 |
|------|----------|
| `error` | 操作失败，需要调查 |
| `warn` | 非预期但可恢复的状态 |
| `info` | 重要业务操作（启动、关闭、关键流程） |
| `debug` | 开发调试信息 |

**禁止**:
- ❌ 生产代码使用 `println!` / `fmt.Println`
- ❌ `console.log` 在生产前端代码中
- ❌ 记录敏感信息（密码、Token、密钥）

---

## 七、安全约束

- ❌ 禁止硬编码密钥/Token/密码
- ❌ 禁止在日志中打印敏感信息
- ❌ 禁止 SQL 拼接（必须使用参数化查询）
- ❌ 禁止用户输入直接拼接到命令/模板

**敏感信息处理**:
- 使用环境变量或配置文件
- 使用 `.env.example` 模板，`.env` 加入 `.gitignore`

---

## 八、测试要求

| 项目 | 要求 |
|------|------|
| 新增公共函数 | 必须配套单元测试 |
| Bug 修复 | 必须有测试用例防止回归 |
| 核心模块 | 必须有集成测试 |

**测试文件命名**:
- Rust: `mod_name.rs` → `mod_name_test.rs` 或 `#[cfg(test)]` 内联
- Go: `xxx.go` → `xxx_test.go`
- 前端: `Component.tsx` → `Component.test.tsx`

## 九、Git 提交规范

### Commit Message 格式
```
<type>: <subject>

<body>
```

### Type 类型
| type | 说明 |
|------|------|
| feat | 新功能 |
| fix | Bug 修复 |
| refactor | 重构（无功能变化） |
| style | 格式调整 |
| docs | 文档更新 |
| test | 测试相关 |
| chore | 构建/工具变更 |

### 示例
```
feat: 添加 TCP Connection Flood 攻击模式

- 实现三次握手保持连接
- 添加连接池管理
- 支持通过 SOCKS5 代理

Closes #123
```

## 十、依赖管理

- ❌ 禁止添加未明确用途的依赖
- ✅ 新增依赖必须说明用途
- ✅ 定期更新依赖（至少每月一次安全更新）
- ✅ 依赖版本锁定在 Cargo.lock / go.sum

### 10.1 不要重复造轮子

**核心原则**: 优先使用成熟库和框架，而不是自己实现已有功能。

#### 选库优先级

| 优先级 | 来源 | 说明 |
|--------|------|------|
| 🔴 首先检查 | 标准库 / 语言官方库 | 最稳定、最了解 |
| 🟠 其次考虑 | 业界公认的主流库 | 社区验证、质量保证 |
| 🟡 谨慎使用 | 不知名/小众库 | 需充分评估维护状态 |
| 🔵 避免使用 | 无人维护的库 | 潜在安全风险 |

#### 必须使用库的场景

```
❌ 自己实现                         ✅ 使用成熟库
─────────────────────────────────────────────────────────
手写 HTTP 客户端                    reqwest (Rust) / wreq / Go net/http
JSON 序列化/反序列化               serde_json / encoding/json
日期时间处理                        chrono / time / Go time
命令行参数解析                      clap / cobra / argparse
数据库操作                         sqlx / diesel / GORM / pgx
Redis 客户端                        redis-rs / go-redis
日志记录                           tracing / log / zap / logrus
配置管理                           config-rs / viper / dotenv
UUID 生成                          uuid / ulid
并发安全/锁                        tokio::sync / std::sync / concurrent-rs
正则表达式                         regex / regexp / re2
URL 解析                           url / net/url
HTTP Server                       axum / actix / gin / echo
WebSocket                         tokio-tungstenite / gorilla/websocket
Validation                         validator / pydantic / zod
Mock 测试                          mockall / gomock / jest.fn()
```

#### 评估新库的标准

引入新库前必须确认:

- [ ] GitHub ⭐ 数量 (参考: >1000 ⭐)
- [ ] 最近更新时间 (3个月内)
- [ ] 是否有稳定版本发布
- [ ] 是否有完整文档
- [ ] 是否有活跃维护
- [ ] 依赖链是否复杂 (依赖过多 = 风险)

提交 PR / Merge 前必须检查:

- [ ] 文件大小不超过限制
