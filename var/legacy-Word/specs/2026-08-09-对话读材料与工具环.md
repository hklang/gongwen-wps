## 0. 为什么是保命工程

用户在空稿上说「读通知，搭半年总结框架」时，若模型只看见 `# 未命名`、看不见 `素材/`，产品等于不能用来写公文。

已拍板：

| 不做 | 原因 |
|------|------|
| 依赖用户再装 Claude Code | 账号、网络、权限、机关认可度差 |
| Claude Code 放在咱们服务器 | **读不到用户本机素材**；上传全文违背「正文/材料在本地」 |
| 插件静默代装整套 CC | 捆绑第三方可改盘 Agent，风险与运维过重 |
| 每轮把全部素材狂贴上云 | 贵、易爆上下文、仍常贴错 |

**要做的是：** 在现有「一个插件 + 云中转」里，自研 **Cursor 式窄工具环**（只服务公文材料，不是编码 Agent）。

## 2. 总架构

```text
┌────────────── 用户电脑（唯一碰磁盘）──────────────┐
│  插件                                           │
│  · 拼本轮上下文（当前稿、选区、文件目录）         │
│  · 执行工具：list / read / search（沙箱内）       │
│  · UI：本轮附带 + 「正在读取 xxx」步骤            │
│  · 改稿提案仍走 Keep，不由工具直接覆写正文        │
└─────────────────────┬───────────────────────────┘
                      │ 多轮 HTTP（同一会话）
                      ▼
┌────────────── 云中转（只跑模型）──────────────────┐
│  入：message + doc_md + context_md + catalog      │
│     + history + tool_results（若有）              │
│  出：final_reply | edit? | tool_calls?            │
│  不存用户正文仓库；不挂载用户磁盘                   │
└─────────────────────────────────────────────────┘
```

原则一句话：**磁盘权威在插件；模型权威在中转；材料按需进入请求，不默认整包上传。**

## 3. 工具白名单（P1 核心）

仅允许工程根内相对路径（边界同工作目录规格；禁止 `..` 与区外）。

| 工具名 | 作用 | 返回 |
|--------|------|------|
| `list_files` | 列出文稿根一层 + `素材/` + `版本/` 的 md（路径、标题、字节） | 清单 JSON |
| `read_file` | 读指定相对路径 md；可带 `max_chars`（默认如 12000） | 文本 + 是否截断 |
| `search_materials` | 在 `素材/` md 内关键词检索，返回命中片段 | 若干 snippet |

**禁止作为工具：** Bash、任意写盘、删文件、访问工程根外路径。  
**写盘：** 仅现有授权改稿 → 预览 → Keep All（与今日一致）。

### 轮次与安全上限

| 项 | 建议 |
|----|------|
| 单次用户消息内工具轮 | ≤ 6 |
| 单文件默认读取 | ≤ 12_000 字（可配置） |
| 单轮 search 命中 | ≤ 5 段 × 每段 ≤ 800 字 |
| 超时 | 单次 tool 执行 ≤ 10s；整轮对话有总超时 |
| 失败 | 工具错误原文回模型；UI 提示「读取失败：路径」 |

| 「本轮附带」元数据（供 UI） | — |

**禁止**在未附带材料时臆造通知内容（沿用现有硬性提示词精神）。

## 5. 记忆 · 轮次 · 超窗压缩（原先方案不足，本章补齐）

> 对标：Cursor（会话转录 + 必要时压缩/新开聊）、Claude Code（`CLAUDE.md` 级项目记忆 + 长对话 compaction）、飞书（会话留在文档侧、云端不替代正文）。  
> **结论分层：本机「记得住」≠ 每轮「全塞进模型」。**

### 5.1 现状（动手前真相）

| 层 | 现网行为 | 问题 |
|----|----------|------|
| 本机会话盘 | `.gongwen/chats/session-*.json`，约保留最近 **80** 条消息，单条截断 20k 字；工程最多约 **30** 个会话 | UI 能翻历史，算「会话级记忆」 |
| 发给模型 | `suggest.py` / 中转侧大致只取 history **最近 6 轮** | 第 7 轮起，更早约定模型看不见（除非仍在当前稿/素材里） |
| 压缩 | **无** | 超窗后是硬截断，不是摘要；工具读过的大段若进 history 会迅速顶满 |
| 工程级长期记忆 | **无**（换「新会话」或清聊天即丢约定） | 「按通知第三章写」跨会话要靠用户重说或正文已 Keep |

旧方案只写「history 上限」，**未设计压缩与工程记忆——此处补板。**

### 5.2 三层记忆（必须分开）

```text
① 工程长期记忆（跨会话，本机）     ← 「这个工程是谁、通知要点、已定框架」
② 会话完整转录（本机 UI / 可回看） ← 用户看见的聊天气泡
③ 模型工作窗（每轮实际上云）       ← 摘要 + 近轮原文 + 本轮材料/工具结果
```

| 层 | 存哪 | 谁维护 | 进模型吗 |
|----|------|--------|----------|
| **① 工程记忆** | `.gongwen/memory.md`（或 `memory.json`：要点列表） | 插件在「Keep 框架 / 用户说记住 / 读完通知」后增量写；可手工编辑 | **每轮带一小段**（如 ≤ 1500 字），换会话仍带 |
| **② 会话转录** | 现有 `chats/session-*.json` | 每条 user/assistant 落盘；工具步骤可记短日志，**不把整份 read_file 正文永久堆进 messages** | 不全量上云 |
| **③ 工作窗** | 请求拼装时临时构造 | 见 §5.4 | 是，受 token 预算约束 |

对标裁剪：

- 学 Claude「项目说明文件」→ 我们的 `memory.md`（公文工程备忘，不是代码规范）。  
- 学 Cursor「长了就压缩 / 脏了就新开聊」→ 自动摘要 + UI「新会话」。  
- **不学**云端永久记忆库（材料与聊天权威仍在本机）。

### 5.3 轮次数字（拍板建议）

分清三种「轮」：

| 名称 | 含义 | 建议上限 |
|------|------|----------|
| **工具轮** | 同一条用户消息内，模型要文件的来回 | ≤ **6**（§3 已有） |
| **会话展示轮** | 本机保存的 user+assistant 条数 | 保留最近 **80～120** 条（与现网同级）；更早可归档或只留摘要 |
| **模型可见轮** | 实际上云的「近原文」对话 | 最近 **12 条消息**（约 6 个来回）**或** 合计 ≤ **约 8k～12k 字**（先到为准） |
| **工程会话数** | `index.json` 里会话条数 | 继续约 **30**；超出淘汰最旧 |

单次用户消息触发的「工具环 + 最终答复」算 **1 次用户轮**，其中可含最多 6 次工具轮；工具中间态默认 **不写进** ② 的气泡（或只写一行「已读素材/通知.md」），避免把 12k×N 写进会话文件。

### 5.4 超窗怎么压缩（工作窗拼装算法）

每轮构造发给中转的 `history` / 附加块，按优先级从高到低塞，直到预算用尽：

```text
[系统提示]
[工程记忆 ① 摘录 ≤1500字]
[会话摘要 session.summary ≤2000字]      ← 有则带
[近轮原文 ③：从新到旧，凑满 12 条或 8k～12k 字]
[本轮：catalog + doc_md + context_md + 本轮 tool_results]
[用户本句]
```

**触发压缩（写/更新 `session.summary`）：**

- 近轮原文将超过预算，或会话消息数 > 24，或估计 token 超阈；且距上次压缩又新增 ≥ 8 条消息。  
- **做法（P1）：** 本机（或走中转一次小请求）把「将被裁掉的旧消息」收成一段中文摘要，写入 session：

```json
{
  "summary": "用户要求按《…通知》搭框架；已约定章节：一…二…；待补：数据口径…",
  "summarizedUntil": 36,
  "readSet": ["素材/xxx通知.md", "素材/初稿.md"]
}
```

- 摘要须保留：**已读材料路径、已拍板结构、未决问题、用户硬性约束**（如「不要写民主生活会」）。  
- 压缩失败则退回硬截断近轮，并 UI 提示「历史较长，仅带最近几轮；重要约定请再提一句或写入工程记忆」。

**工具结果进历史的纪律（防爆窗）：**

| 内容 | 进 ② 会话气泡 | 进 ③ 工作窗 |
|------|----------------|-------------|
| 助手最终 reply | 是 | 近轮内是 |
| 本轮 `read_file` 全文 | **否**（只记「已读 path」） | **仅本轮** tool_results；下轮靠 `readSet` + 必要时再 read |
| 旧轮工具原文 | 否 | 否（摘要里留路径与要点） |

### 5.5 「长期记忆」用户怎么感知（UI）

| 能力 | 行为 |
|------|------|
| 同会话连续聊 | 近轮原文 + 摘要；侧栏可回看全文气泡 |
| 换「新会话」 | ② 清空；**① 工程记忆仍带**（通知要点、已定框架若已写入） |
| 换工程 | ①② 都换根，不串 |
| 手动 | 「写入工程记忆」把选中约定追加进 `memory.md`；设置里可打开编辑 |
| 脏上下文 | 提示「新开会话」；对标 Cursor 卫生习惯，不硬撑无限窗口 |

### 5.6 和工具环的关系

- 工具环解决 **「这一枪如何读到通知」**。  
- 记忆层解决 **「第三十枪是否还记得通知要求与已定框架」**。  
- 二者缺一：要么当轮读不到，要么长聊忘约定。  
- `readSet`：本会话已读路径列表；模型再要同一文件时，可先给「摘要中的要点 + 是否重新 read」提示，避免无脑重贴全文。

### 5.7 分期（记忆相关）

| 期 | 做 | 验收 |
|----|----|------|
| **P0** | 明确上云近轮条数（如 12 条）与目录/素材摘录；UI 不假装「全程记得」 | 文档与状态栏/附带条一致 |
| **P1** | `session.summary` + `readSet` + 超窗自动压缩；工具正文不进气泡 | 聊过 20+ 轮后仍能答出「先前定的章节名」；会话文件不因多次 read 膨胀失控 |
| **P2** | `.gongwen/memory.md` 工程记忆 +「写入工程记忆」；新会话仍带 ① | 新会话第一句无需重贴通知，也能按记忆中的通知要点答（记忆未写则提示去读素材） |

## 5A. 本地索引：要多强？大厂怎么做？能不能直接用？

> 问题本质：让模型**少猜、少读全文**，用小索引定位到该 \
ead_file\ 的路径，从而省 token。  
> **不是**一上来就上 Cursor 级向量云索引。

### 5A.1 大厂常见做法（对标）

| 产品 | 做法摘要 | 和咱们的关系 |
|------|----------|--------------|
| **Cursor** | 本地切块 → 服务端算 embedding → 向量库只存向量+模糊路径；查询语义召回 → **本机再读原文**；另有关键词；Merkle 增量同步 | 学「索引只指路、正文仍本地读」；**不能直接用**其私有索引 |
| **Claude Code** | 偏 Agent：Grep / Glob / Read 现场搜，不依赖重型永久向量库 | 公文材料量小时，这条更贴近 |
| **Continue / 本地 RAG 开源** | 自建或本地向量 + codebase 检索 | 可参考，嵌入成本≈再做一个子系统 |
| **飞书知识库类** | 云端切片+检索 | 材料上云，与「正文本机」冲突，不当主路径 |

共性是 **分层检索**，不是「索引越强越好」：

\\\	ext
目录/元数据（极便宜）→ 关键词/字面检索 →（可选）语义向量 → 最后 read 原文进提示词
\\\

### 5A.2 咱们体量：不需要「极强向量索引」才能省 token

公文工程典型：根下几个 md + \素材/\ 十余篇，不是百万行代码仓。

| 强度 | 内容 | 何时 |
|------|------|------|
| **L0 目录（必做）** | 路径、标题、字节、mtime、可选前 200 字 | **P0**；每轮 catalog，模型点名再 read |
| **L1 关键词（主路径）** | \search_materials\ 本机扫/简单倒排 | **P1**；「通知」「半年」够定位 |
| **L2 语义向量（可选）** | 本机小向量库 | 仅素材很多且 L1 常找错时再立项 |
| **L3 Cursor 云索引** | 切片上传算向量 | **不做主路径** |

省 token 的关键：**catalog 点名 + search 定位 + read 一篇**，不是每轮贴十份全文。

### 5A.3 「找到了直接用」——结论

| 候选 | 能否整包当内核 |
|------|----------------|
| Cursor 代码索引 | **否**（闭源、绑其云与账号） |
| Claude Code 检索 | **否**（要装 CC） |
| Continue / CodeIndexer / mcp-local-rag / RAGnarok 等 | **不建议整包嵌入**（向量库+嵌入模型+MCP，安装面过大；公文体量用不上） |
| 本机字符串扫描（ripgrep 思路） | **用这个思路**（即 P1 \search_materials\，零新重依赖） |

**可复用的是模式，不是装一个现成索引产品替代插件。**

### 5A.4 落盘与上云纪律

- L0 可缓存 \.gongwen/index.json\（mtime 失效刷新）。  
- L1 材料少时可每次扫盘，不必先上向量库。  
- 上云：只传命中 snippet 或点名后的 read 结果；**不**默认上传全库。  
- \memory.md\ 记约定；index 记「盘上有什么」——分工不同。

### 5A.5 索引分期

| 期 | 做 |
|----|----|
| **P0** | L0 catalog |
| **P1** | L1 search + read |
| **P2+** | 验收仍找错文件再考虑 L2 |

## 6. 协议形态（A 已拍板；第二包升到原生 tools）

### 6.1 对客户端（插件 ↔ 中转）

中转 `/api/chat` 在需要读盘时返回：

```json
{
  "ok": true,
  "type": "tool_calls",
  "tool_calls": [
    { "id": "1", "name": "read_file", "arguments": { "path": "素材/xxx通知.md" } }
  ],
  "reply": "",
  "edit": null
}
```

最终：

```json
{
  "ok": true,
  "type": "final",
  "reply": "…",
  "edit": null
}
```

插件识别 `tool_calls` → 本机执行 → POST `tool_results` → 直至 `final` 或触顶。  
文本 JSON / `need_files` 仅作**解析回退**（旧中转或 MiniMax），不是 DeepSeek 主路径。

### 6.2 对模型（中转 ↔ DeepSeek）

- 请求带 OpenAI 兼容 `tools`（三工具 schema）。  
- 若上轮有 `tool_results`：拼成 `assistant.tool_calls` + `role:tool` 消息，**不要**再把同一份结果粘进 user 正文。  
- `finish_reason=tool_calls` → 映射为 §6.1 结构；否则走 final / 改稿 JSON 解析。

**循环只在本机插件编排**；中转无磁盘、无会话态。

## 7. UI（必须有，否则用户仍觉「读不到」）

对标 Cursor 步骤条 + 飞书「引用了什么」。

输入框上方（或消息内系统行）固定可见：

1. **本轮附带：** 当前文稿 · 目录 N 项 · 已读文件列表 · 是否授权改稿  
2. **进行中：** `正在读取 素材/xxx.md` / `正在检索「通知」`  
3. **可操作（P2）：** 「+ 材料」从侧栏勾选钉入本轮  

空稿且未读到任何素材时，助手应明确说「目录里没有可用通知/材料」，而不是编框架数字。

## 9. 分期与验收

### P0 — 止血（可先于完整工具环）

**目标：** 不再出现「全文只有未命名 → 无法构思」的误拒（在素材夹确有 md 时）。

| 做 | 验收 |
|----|------|
| 对话请求始终带工程目录（路径+标题+字节） | 模型回复能点名素材文件名 |
| 空稿，或用户话含「通知\|素材\|框架\|提纲\|根据材料」时，**自动附带素材摘录**（与授权无关） | 未勾授权也能按通知谈框架要点 |
| UI 一行「本轮附带：…」 | 用户看得见带了什么 |

### P1 — 工具环（主路径）

**目标：** 与 Cursor 同构的「要啥读啥」。

| 做 | 验收 |
|----|------|
| 三工具 + 多轮编排 + 上限 | 空稿：「请读取通知并搭半年总结框架」→ 出现读取步骤 → 左侧/回复给出贴合通知的章节骨架 |
| 路径沙箱 | 区外路径被拒并提示 |
| 授权改稿时 `edit` 仍经 Keep | 未 Keep 不落盘 |

**金标准验收句（手工）：**

1. 工程 `素材/` 放入真实通知 md（由 docx 转换亦可）  
2. 打开空的总结 md，右侧对话（可授权）  
3. 输入：`请读取素材里的通知，按通知要求搭半年工作总结框架`  
4. 可见读取步骤 → 框架预览 → Keep 后磁盘章节正确  

### P2 — @ / 勾选钉材料 + 工程记忆

| 做 | 验收 |
|----|------|
| 侧栏或输入区钉文件进本轮 | 钉了谁，附带条显示谁；优先于自动选型 |
| `.gongwen/memory.md` + 「写入工程记忆」 | 新会话仍能按工程记忆中的通知/框架要点续聊 |

记忆相关细则见 §5.7（P0 说清窗口；P1 会话摘要；P2 工程记忆）。
