# Wroder6 · 工程编辑器 UI 方案

> 日期：2026-08-09  
> 状态：第一期已落地（左侧工程栏 + 壳内打开中/面包屑/前进后退 + 本工程会话）；查看模式后续  
> 一句话：**产品是「工程内的公文编辑器」**；中间写稿/查看，右侧是**当前工程**的对话与历史，不是全局闲聊窗口。

---

## 1. 产品形态

| 概念 | 含义 |
|------|------|
| **工程** | 工作区根（有 `.gongwen/`、`素材/`、`版本/` 的那一层） |
| **文稿** | 工程内某个 `.md`（左侧主编辑区） |
| **会话** | 挂在「工程」上的对话线程（可多条）；打开右侧时默认进**本工程最近一条** |

原则：

1. **编辑器是主界面**（占大部分宽度），不是 AI 产品套一层编辑。  
2. **右侧能力从属于工程**：换工程 → 聊天历史跟着换；同工程换文稿 → 历史仍在，上下文指向当前文稿。  
3. **查看与编辑是同一壳子的两种模式**，不是两套页面。  
4. 云端只出文本建议；历史与文件只落**本机工程目录**。

---

## 2. 整体布局（三栏可收）

```text
┌─ 文件▾ │ 保存▾ │ 导出▾ │ 转换▾ │ 设置▾ ─ 文稿名 ─ 工程·状态 ─┐
├─（多稿时）打开中页签 ──────────────────────────────────────────┤
├──────────┬──────────────────────────────┬────────────────────────────┤
│ 工程树   │  主区：编辑 / 查看            │  右侧：本工程 AI           │
│ (可收)   │  md 所见即所得               │  会话列表 + 当前聊天       │
│ 文稿     │  查看态隐藏格式栏            │  改稿预览条 Keep/Undo      │
│ 素材     │                              │                            │
│ 版本     │                              │                            │
└──────────┴──────────────────────────────┴────────────────────────────┘
```

顶栏对齐 **Word / WPS** 习惯（对标与反模式见 `Word/Code/大厂构思.md`）：「文件」收拢新建/打开/导出/关闭；保存进快速区；标题居中；禁止裸按钮一排 + 远处「⋯」。

宽度建议（桌面）：

- 工程树：约 200px，可折叠；折叠后顶栏留「工程」按钮  
- 主区：弹性占满  
- 右侧：约 360–400px，可折叠；折叠后顶栏留「对话」按钮  

VS Code 嵌入时：工程树可用资源管理器代替（第一期可不做左侧树，只做顶栏工程名 + 右侧会话）。

---

## 3. 主区：编辑 / 查看

### 3.1 编辑模式（默认）

- 现有 Vditor + 格式工具栏 + 自动保存  
- 顶栏：文件菜单 + 保存菜单 + 定时保存(默认开)/定时存版本(默认关)；文稿名居中  

### 3.2 查看模式

- 同一份 md，**只读渲染**（仍用同一预览样式，禁用输入与格式栏）  
- 用途：对照素材、审稿、演示；右侧对话仍可问，但默认**不勾选授权改稿**  
- 切换：顶栏分段按钮 `编辑 | 查看`；快捷键可后加  

### 3.3 改稿预览（叠加态）

- 授权对话产生改稿时：主区进入预览（现有 Keep / Undo / Review）  
- 查看模式下若需改稿：提示先切回编辑，或一键「转编辑并预览」  

---

## 4. 右侧：工程级聊天（核心）

### 4.1 信息架构

```text
右侧
├─ 顶：本工程名 · 当前文稿短名
├─ 会话条：最近会话下拉 / 「新会话」
├─ 模式：写作 | 校对（沿用）
├─ 消息流：本会话历史（可滚动）
├─ 改稿条：有 pending 才出现
└─ 输入区：授权改稿 · 发送 · 清空本会话
```

### 4.2 历史挂在哪

| 范围 | 规则 |
|------|------|
| 持久化位置 | 本机 `.gongwen/chats/`（按工程） |
| 文件建议 | `session-<id>.json` + `index.json`（标题、更新时间、关联文稿可选） |
| 打开右侧 | 加载**当前工程**的 index → 打开最近一条；无则自动建「新会话」 |
| 换工程 | 整侧栏重载，**不出现**上一工程的消息 |
| 换文稿（同工程） | 历史保留；输入框上方显示「针对：当前文件名」；可选「钉到本文件」过滤（二期） |
| 清空 | 只清**当前会话**；二次确认；不影响其它会话 |

### 4.3 会话列表（轻量）

- 下拉即可，不必做成复杂侧栏内再侧栏  
- 每项：标题（首条用户话截断）· 相对时间  
- 「新会话」：空白线程，旧的仍在列表里  

### 4.4 与「出方案」的关系

- **对话**：默认；带工程历史；可授权改稿  
- **出方案**：仍是「对当前选区出多套」，结果挂在**当前会话**里一条「方案卡片」消息（或单独子状态），避免两套互不相干的记忆  

第一期可先做到：出方案不进历史正文，只保留对话轮次；二期再把方案摘要写入会话。

## 5. 工程树（第一期可选）

若做左侧树，只显示三块，避免像 IDE 全家桶：

1. **文稿** — `work/` 与根下 md（不含 `版本/`）  
2. **素材** — `素材/`（引导用户往这放）  
3. **版本** — `版本/`（只读打开到查看模式）  

点击素材 md → 主区**查看**打开（或分屏二期）；点击文稿 → 编辑打开。

VS Code 路径：第一期不做树，用资源管理器 + 状态栏「工程：××」。

---

## 6. 关键路径（UI 要服务的行为）

1. 打开工程内某 md → 顶栏显示工程名 → 右侧自动出现**该工程**上次聊天  
2. 用户说「搭框架」→ 授权 → 预览 → Keep → 历史里留下这一轮  
3. 关掉再开同一工程另一文件 → 右侧仍是同一串历史，提示针对新文件  
4. 开另一个文件夹工程 → 右侧换成另一套历史  
5. 切「查看」读素材 → 回来「编辑」继续写；聊天不断档  

---

## 7. 视觉与信息优先级（克制）

- 主区干净：公文纸感沿用现网，不加重仪表盘  
- 右侧：消息气泡简洁；系统提示（授权、预览）用一条细状态，不堆卡片墙  
- 工程名在顶栏**始终可见**（解决「我到底在哪个工程」）  
- 少徽章、少统计条；需要时只在状态栏一行字  

---

## 8. 分阶段落地（只 UI/交互相关）

| 阶段 | 做什么 | 验收 |
|------|--------|------|
| **U1** | 工程标识 + 右侧会话持久化到 `.gongwen/chats/` + 打开即恢复本工程历史 | 换工程历史必变 |
| **U2** | 顶栏「编辑 \| 查看」；版本/素材用查看打开 | 查看不能误改正文 |
| **U3** | 会话下拉 + 新会话；清空仅当前会话 | 多会话不串 |
| **U4** | （可选）工程树三区；VS Code 可继续用资源管理器 | 树与打开行为一致 |

安全红线不变：历史只在本机；云中转无历史库、无文件权。

---

## 9. 明确不做（本方案范围外）

- 全局跨工程统一聊天箱  
- 云端同步聊天记录  
- 复刻完整 IDE（终端、Git 面板、调试）  
- 右侧同时开多个浮动聊天窗

## 10. 已拍板：打开策略 + 文件管理范围

### 10.1 打开：咱们自己管（VS Code 只是壳）

- 主路径：编辑器顶栏「打开 / 创建」+ 工程内点选；对用户是 **Wroder6 在开文件**。  
- **同壳切换**：工程内打开软换正文，不堆多个带聊天的 VS Code 页。  
- **换工程根**（创建/打开落到另一目录）：视为新工程，清空上一工程页签/对话内存，从该目录 `.gongwen` 重载配置与会话。  
- **怎么回去**：顶栏工程名 +「打开中」细线页签（无面包屑/无←→）；回稿点页签或左侧列表；重命名合并页签。  
- VS Code 资源管理器双击：允许当快捷方式，不作教程主入口。  
- 创建与打开分开；创建落到当前工程内。

### 10.2 文件管理：要做，但不做成资源管理器

**会不会很复杂？** —— 范围收窄后 **不复杂**。我们做的是「工程内 md 列表」，不是完整文件管理器。

| 做 | 不做 |
|----|------|
| 只列 **当前工程根下** 的 `.md` | 不管图片/docx/文件夹任意浏览 |
| 分区：文稿=**工程根一层** / `素材/` / `版本/`（皆为 md） | 不扫 `src2/`、`work/` 等其它目录 |
| 打开、新建、重命名（确认后）、刷新列表 | 不复制移动复杂操作；**不删除**（或极后期再加） |
| 路径沙箱：禁止 `..` 与区外 | 不提供「打开任意路径」当主功能 |

扫描规则（与现网一致并收紧）：

- **工作目录 = 打开/创建的那个 md 所在目录**（在 `素材/`、`版本/`、`work/`、`快照/` 内则上抬一级）；不再向上绑父级工程，也不回落 VS Code 工作区根  
- 列表与 AI 素材：**只** 文稿根一层 / `素材/` / `版本/`；**不扫** `src2/`、`终稿/`、`work/` 等  
- 只认 `.md`；跳过 `.gongwen/`、`.git`、`Word/` 等  

这样左侧（或顶栏下拉）就是一张 **md 清单**，工作量可控，和「工程聊天」「素材优先」同一套根目录模型。

### 10.3 会话粒度（一并定）

- **按工程**一条常用会话 + 可「新会话」  
- 第一期 VS Code：**可先不做左侧树**，用「文件」下拉/面板列当前工程 md；独立窗口再上三区树。

---

通过后从 **U1（工程标识 + 聊天历史）** 与 **文件清单（当前工程 md）** 开工。
