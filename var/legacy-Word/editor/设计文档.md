# 公文所见即所得编辑器 —— 设计文档 v2

- **日期**：2026-08-06
- **状态**：待评审
- **位置**：`Word/editor/`（与 `tools/`、`writer/` 平级，可整体移植）
- **工具形态**：本地小工具。`python app.py` 一键启动 → 浏览器打开带"打开/保存/导出"按钮的所见即所得编辑器；docx↔md 转换全部后台自动完成。

## 一、要解决的问题

人机双向写双向更新公文 Word 文档：

- **人**：点"打开"选一个本地 docx/md → 后台自动转成 md 并打开所见即所得编辑器 → 编辑内容**实时存进本地 md**（绝不丢数据）→ 点"保存"后台自动把 md 转回 docx。
- **机**：Claude 在 VSCode 里改同一份 md，两边互相能看到。
- **双向**：人改、机改都落进同一个 md 文件，最终能转出规范排版的 docx。

## 二、核心原则

1. **md 是唯一真相**。浏览器只是 md 的"Word 化编辑壳"；Claude 改的也是这份 md。
2. **数据永不丢**。所有编辑实时自动保存到本地 md（原子写入 + 快照备份 + 关闭前 flush）。这是最高优先级。
3. **转换零手操**。docx→md、md→docx 全部由后台调用现有 `tools/docx2md.py` / `tools/md2docx.py`，前端只点按钮。
4. **不做分页/页码**。真分页由转出的 docx 在 Word 里完成。
5. **可移植**。整个 `editor/` 目录复制到任意新项目即用。

## 三、总体架构与数据流

```
python app.py 启动本地后端（复用 tools/ 的两个转换脚本）
        │
用户点"打开" → 选本地 docx/md → POST /api/open
        │                             └─docx则后台跑 docx2md.py → work/当前.md
        ▼
浏览器所见即所得编辑（Vditor）
        │ 每次编辑防抖自动保存 + Ctrl+S
        ▼
POST /api/save → 原子写入 work/当前.md（先写.tmp再rename）+ 生成快照_时间戳.md
        │
双向：Claude 在 VSCode 直接改 work/当前.md → 前端轮询发现变化 → 提示"重新加载"
        │
用户点"保存"→ 后台跑 md2docx.py → 产出 docx → 浏览器下载；同时 md 可另存
```

## 四、目录结构

```
Word/editor/
├── app.py            ← 本地后端（Python 标准库，零额外依赖；内部调用 ../tools/ 的转换脚本）
├── editor.html       ← 前端：打开/保存/导出按钮 + Vditor 所见即所得
├── gongwen.css       ← 公文皮肤：排版规范翻译成 CSS（核心资产）
├── vendor/vditor/    ← Vditor 本地打包（js/css/icons，离线可用）
├── work/             ← 工作目录（自动生成）：当前.md + 快照_时间戳.md + 输出.docx
└── 设计文档.md
```

## 五、后端接口（app.py，Python 标准库 http.server）

| 接口 | 作用 |
|------|------|
| `GET /` | 返回 editor.html |
| `GET /res/*` | 静态资源（gongwen.css、vditor、js） |
| `POST /api/open` | 接收上传的 docx/md；docx 则调用 docx2md 转 md，写入 `work/当前.md`，返回 `{文件名, md内容}` |
| `POST /api/save` | 接收 md → 原子写入 `work/当前.md` + 生成快照 | 
| `GET /api/content` | 返回当前 md 内容与哈希（用于重新加载/轮询外部改动） |
| `GET /api/export?fmt=docx` | 调用 md2docx 转 docx，返回下载（写入 `work/输出.docx`）；`fmt=md` 返回 md 下载 |
| `GET /api/poll` | 返回当前 md 哈希，前端定时轮询检测 Claude 的外部改动 |

启动：`python app.py`（机器上 Python 被商店劫持时用 anaconda 全路径，与 tools/README 一致）。

## 六、能力与格式映射

应用户约束：**纯文字 + 简单表格，无图片**。

| md 写法 | 编辑器显示（所见即所得） | 对应 docx 效果 |
|---------|------------------------|---------------|
| `# 标题` | 宋体 二号 加黑 居中 | 大标题 |
| `## 一、xxx` | 黑体 三号 首行缩进2字符 | 一级标题 |
| `### （一）xxx` | 楷体 三号 加黑 首行缩进2字符 | 二级标题 |
| `#### 小标题` | 仿宋 三号 加黑 无缩进 | 三级标题 |
| `**前缀。**正文` | 段内加粗：前缀黑、正文正常 | 段内混排 |
| `**整段**` | 整段加黑 | 整段加黑 |
| 正文段 | 仿宋 三号、首行缩进2字符、行距固定30磅 | 正文 |
| GFM 表格 | Table Grid、表头灰底加粗、居中 | 表格 |
| `<div align="right">` | 右对齐（署名/日期） | 右对齐 |

**明确不做**：图片、附件、分页、页码、页眉页脚、复杂表格跨页。

## 七、数据安全（最高优先级，逐条落实）

用户红线：**实时编辑必须存到本地 md，千万不能丢数据。**

1. **自动保存**：每次编辑停止后防抖 1~2 秒 → 自动 POST /api/save；另有显式保存按钮 + Ctrl+S。
2. **原子写入**：先写 `当前.md.tmp`，再 `os.replace` 覆盖 `当前.md`——写一半断电也不会产生半截文件。
3. **快照备份**：每次保存前把上一版复制为 `work/快照_YYYYMMDD_HHMMSS.md`，保留最近 20 份。md 坏了随时从快照找回。
4. **关闭前 flush**：页面 `beforeunload` / 隐藏时把未保存内容立即发一次保存，兜底误关。
5. **原始文件永不覆盖**：打开的 docx 原样不动；导出 docx 是全新文件。
6. **md 始终在本地磁盘**：`work/当前.md` 是真实文件，Claude（VSCode）随时可读可改。

## 八、双向机制（人 ↔ Claude）

- 人的编辑：自动保存到 `work/当前.md` → Claude 在 VSCode 打开即可见。
- 机器的改动：Claude 改 `work/当前.md` → 前端每 3 秒 `/api/poll` 比对哈希 → 检测到变化提示"重新加载"，点击后取回新内容（本地改动未保存时会先提醒，避免互相覆盖）。
- 冲突：按先后顺序使用；检测到"双方都改过"时以弹窗让用户选择"以本地为准/以磁盘为准"。

## 九、已知边界与风险

| 风险 | 对策 |
|------|------|
| Vditor 默认过滤内联 HTML | 配置开启，保住 `<span【】>` 探测标记透传 |
| 右对齐导出格式可能与 `<div align="right">` 不一致 | gongwen.css / 胶水层做导出后处理映射 |
| 浏览器兼容 | 主推 Edge/Chrome；导出走"下载"兜底，全浏览器可用 |
| 转换脚本异常 | 后端捕获异常返回错误提示，md 数据不受影响（转换失败≠数据丢失） |
| 中文输入法 | Vditor 原生处理 IME，所见即所得模式稳定 |

## 十、验收标准

1. **打开即转换**：点"打开"选本地 docx → 自动转 md 并打开所见即所得，格式正确。
2. **实时落盘**：编辑停顿几秒后，`work/当前.md` 已包含最新内容；强关/刷新后重开仍在。
3. **往返一致**：md 再导出，与打开时内容 diff 几乎一致（含加粗/表格/右对齐）。
4. **保存即转换**：点"保存" → 自动出 docx，与编辑器所见格式一致（字体/缩进/行距/表格）。
5. **格式对照**：同 md 的编辑器截图 vs docx 截图肉眼一致。
6. **双向**：Claude 改 md → 前端提示重新加载可见；人保存 → Claude 读得到。
7. **可移植**：复制 `editor/` 目录到空目录，`python app.py` 即可用。
