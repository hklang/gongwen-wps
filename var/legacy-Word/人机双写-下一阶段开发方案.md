> 日期：2026-08-08

> 范围：在现有 `Word/editor` 基础上，走向「轻安装 + 本地文件 + 服务器能力」

## 1. 目标（一句话）

**本地操作文稿与参考材料，界面可嵌在 VS Code 中间；AI 与业务网页由服务器提供；用户安装尽量只装一个插件。**

成功标准：

1. 打开本地 `.md`（及后续 docx 流程）可编辑，改动能**实时写回本地**  
2. 能读取工作区内**其它本地文件**作数据源（素材、旧稿、提纲）  
3. 出方案 / 对话质量可用，走**服务器模型中转**（不依赖本机配一堆 Key）  
4. 安装路径短：有 VS Code/Cursor → 装扩展 → 登录/填服务器地址即可用  

非目标（本阶段不做）：

- 服务器上装 Claude Code 当主引擎  
- 编辑器内再接 Cursor SDK  
- 在 VS Code 里完整复刻 Word 红头排版（定稿仍靠导出 docx）

| 议题 | 结论 |
|------|------|
| 主路径 AI | **直接调模型**（DeepSeek / MiniMax），不要 Claude Code 中转 |
| 服务器角色 | **模型中转 +（后续）托管写作页**，不是装 Claude Code |
| Cursor 提供商 | **已从编辑器去掉**；Cursor VIP 登录 ≠ SDK Key |
| 本地 vs 云端稿 | **以本地操作为主**；服务器页不能单独读写本机文件，必须有**本地桥** |
| VS Code | 值得做：中间开网页/自定义编辑器 + 插件当桥，减轻安装 |
| 质量优先 | 架构服务于「写出来能用」；默认模型与提示词用实稿采用率说话 |

## 3. 总体架构

```text
┌─────────────────── 用户电脑 ───────────────────┐
│  VS Code / Cursor                               │
│  ┌─ 插件（本地桥，安装物）──────────────────┐  │
│  │ · 打开中间 Webview / Custom Editor         │  │
│  │ · 读/写本地 md，实时保存                   │  │
│  │ · 按需读取工作区其它文件作上下文           │  │
│  │ · 把内容 postMessage ↔ 页面               │  │
│  └───────────────────┬────────────────────────┘  │
│                      │ HTTP(S)（现网：8080 反代） │
└──────────────────────┼───────────────────────────┘
                       ▼
┌─────────────────── 云机 49.233.190.103 ─────────┐
│  · 模型中转 gongwen-relay（已上线，见阶段 A）     │
│  · 写作前端托管（阶段 C，未做）                   │
│  · DeepSeek / MiniMax Key 仅服务器               │
└──────────────────────────────────────────────────┘
```

原则：

- **文件权威在本地**（插件写磁盘）；服务器不默认存用户全文（除非以后做云同步，另立项）  
- **模型权威在服务器**（Key、额度、选模）——阶段 A 已通  
- **现有 `Word/editor` 为产品内核**：提示词、出方案 JSON、采用写回、禁改稿逻辑尽量复用  
- **数据留存优先于炫技 UI**（见 §3.1）；阶段 B 未满足安全包前不嵌完整双写页  

### 3.1 数据留存红线（调研结论 · 必须遵守）

> 你最在意的是 **md 不丢**。下面是对照现有编辑器 + VS Code 惯例后的硬规则。

**现有本地编辑器已经具备（应原样继承到插件）：**

| 机制 | 现状 | 作用 |
|------|------|------|
| 权威文件 | `work\<名>.md` | 人改 / AI 采用都写这里 |
| 原子写入 | `atomic_write`（先 `.tmp` 再 `replace`） | 避免写一半坏文件 |
| 滚动快照 | `work\快照\` 最近 20 份 | 误改可找回 |
| 命名版本 | `work\var\<名>_时间.md` | 主动存档 |
| 重开保护 | 已有 md **不**被 docx 重转覆盖（除非确认） | 防「打开一次清空」 |
| 源 docx | **永不覆盖**；导出另存 `work\` | 原稿安全 |
| 外部变更 | 轮询 hash，提示同步 | 与 Cursor/外编共存 |

**新架构里最危险的三种丢数据方式（禁止出现）：**

1. **服务器当正文仓库**：远程页自己存一份 md，和本地双份 → 必冲突、必丢一边。  
   → **服务器只跑 UI/AI；正文只落本地磁盘。**  
2. **自写 Webview 存盘绕过 VS Code**：自己 `fs.writeFile` 覆盖，丢掉 VS Code 的脏检查 / Hot Exit / 冲突提示。  
   → **md 正文优先走 `CustomTextEditor` + `TextDocument` / `WorkspaceEdit`**，吃上自动保存与冲突检测。  
3. **「重新打开 / 重新转换」静默覆盖已有 md**。  
   → 沿用现编辑器：有 md 先加载；覆盖必须二次确认，且覆盖前快照。

**展示与开发分工（避免「好看」牺牲「可靠」）：**

| 层 | 做什么 | 不做什么 |
|----|--------|----------|
| 展示（Webview/Vditor） | 所见即所得、选区、预览方案 | 不单独当权威库 |
| 留存（本地 md） | 唯一正文；Git/资源管理器可见可拷 | 不把全文默认上传中转 |
| AI 中转 | 只收选区/必要上下文做出方案 | 日志若落盘须脱敏、可关、不替代正文 |

**插件侧建议的最小安全包（阶段 B 必做）：**

1. 打开即绑定真实磁盘路径上的 `.md`（不是无名缓冲区）  
2. 编辑 → debounce → 写入同一路径（原子写或经 VS Code save）  
3. 每次落盘前/后保留快照（复用或移植 `snapshot()` 逻辑到工作区旁 `快照/`）  
4. 外部改文件：提示「磁盘更新」，默认不吞掉未保存编辑  
5. 采用 AI 方案 = 改 `TextDocument` 再保存，与人手改同一条链路  
6. 中转失败只影响出方案，**绝不清空或改写本地 md**

**一句话红线：本地 md 是唯一真相；快照是保险；服务器碰不到「覆盖正文」的权限。**

## 6. 插件内模块划分（阶段 B）

```text
vscode-gongwen/          （建议新目录，与 editor 并列或放 Word/extension）
  package.json           命令、customEditors、配置项
  src/extension.ts       激活、注册编辑器/命令
  src/fileBridge.ts      读文档、applyEdit、保存、读参考文件
  src/webviewHost.ts     Webview/CSP、postMessage 协议
  media/ 或 web/         打包后的双写前端（或 URL）
```

**postMessage 协议（草案）**

| 方向 | type | 含义 |
|------|------|------|
| 扩展→页 | `init` | 初始 md、只读标志、服务器 baseUrl、token |
| 扩展→页 | `doc` | 外部改文件后的全文刷新 |
| 页→扩展 | `edit` | 正文变更（防抖后扩展写入 TextDocument） |
| 页→扩展 | `save` | 立即保存 |
| 页→扩展 | `readFiles` | 请求读取工作区相对路径列表 |
| 页→扩展 | `ai` | 也可改为页直连服务器 API（扩展只注入 token） |

推荐：**AI 请求由页面直连你们服务器**（扩展注入地址与 token），避免所有流量绕扩展；**文件只走扩展**。

## 7. 配置与安全

- 用户配置：`gongwen.serverUrl`、`gongwen.token`（SecretStorage 存 token）  
- 服务端：Key 不进仓库、HTTPS、按用户限流  
- Webview：限制可加载的脚本源；若嵌远程页，白名单域名  
- 本地参考文件：默认仅工作区内路径，禁止任意盘符扫描
