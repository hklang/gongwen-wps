## 三、md 编写约定（关键）

### 3.1 标题用 `#` ~ `####`，编号项用 `**`

```
# 关于xxx的通知              ← 大标题，居中

## 一、报送内容               ← 一级标题，黑体
### （一）工作成效             ← 二级标题，楷体加黑
#### 独立小标题               ← 三级标题（真标题用，编号项不用）

**一是尽快组织调研。**后续计划安排... ← 段内混排：前缀加黑，后续不加黑
**1.五年对比：**与十三五相比...       ← 段内混排：前缀加黑，后续不加黑
**1.年度工作亮点**                   ← 整段加黑（独立编号行）
请各部室...                          ← 后续正文
```

### 3.2 段内混排规则（重要）

`**前缀。**正文` 或 `**前缀：**正文` → 前缀加黑，正文正常，**同段不退行**。

关键：`。` 或 `：` 必须在 `**` 之前，作为加黑与不加黑的分界点。

- 正确：`**一是尽快组织大连调研。**后续计划...` → "一是...调研。"黑，"后续计划..."正常
- 错误：`**一是尽快组织大连调研。 后续计划...**` → 整段黑（`**` 括到了末尾）

### 3.3 编号项不要用 `####`

原文 `1.xxx` 往往不是标题，而是同一段落内加粗前缀+正文。
- 错误：`#### 1. 五年对比变化` → 多了空格，拆成了两段
- 正确：`**1.五年对比变化：**与十三五...` → 一段，前缀加黑

### 3.4 注释行用全角括号

- `*（字数：约600字）*` → 去掉首尾 `*`，输出为 `（字数：约600字）`
- 注意：正则要匹配全角 `（）`，不能写成半角 `\(\)`

### 3.4 署名/日期用 `<div align="right">`

```html
<div align="right">集团综合办公室</div>
<div align="right">2025年12月9日</div>
```

### 3.5 禁止分页符

`---` 在脚本中被跳过，不起任何作用。不要用 `---` 分隔内容。

## 四、踩坑清单

| 序号 | 问题 | 原因 | 解决 |
|------|------|------|------|
| 1 | 纸张不是A4 | PaperSize=9 在本机对应A5 | 从原版docx实测，本机A4=7 |
| 2 | 标题有缩进 | 新段落继承上段格式，未显式清零 | 每个段落**始终**设置 `CharacterUnitFirstLineIndent`（标题=0，正文=2） |
| 3 | 编号后多空格 | `#### 1. xxx` 的 ` ` 被当内容输出了 | 改用 `**1.xxx：**` 格式 |
| 4 | 编号后换行 | `#### 1.` + 单独正文行 | 同上，`**1.**正文内容` 合为一段 |
| 5 | `*` 号残留 | 全角括号 `（）` 被正则 `\(` 匹配 | 正则用 `（` `）` 匹配全角 |
| 6 | 空行变空段 | md 空行被转为 Word 空段落 | 脚本中 `if ($t -eq '') { continue }` 跳过 |
| 7 | `**前缀**正文` 整段加黑 | 原正则合并文本后整段加黑 | 改为段内混排：前缀Range加黑，正文Range不加黑 |
| 8 | Words SaveAs 报错 | `[ref]` 在 PS5.1 不兼容 | 改用 `$doc.SaveAs($path.ToString(), 16)` |
| 9 | H1空行位置反了 | Document.Add 自带初始空段 | 开局 `$doc.Range(0,1).Delete()` |
| 10 | `。**` 后有空格 | regex `\*\*(.+)` 把空格也吃进去了 | 改为 `\*\*\s*(.+)`，`\s*` 吃掉空格 |
| 11 | 页码不居中 | `PageNumbers.Add(0)` = 左对齐 | 居中 = `Add(1)`，右对齐 = `Add(2)` |
| 12 | `**标题。**正文`行内重复匹配 | `^\*\*(.+)\*\*$` 先吃了前半段星号，正文被漏掉 | 源文件用 PS 全局替换去星号；写作约定：`**` 仅用于编号前缀，独立小标题不用 |
| 13 | 段内混排Range坐标偏移 | 混排加黑Range从doc.Range计算，坐标漂移 | 从`$p.Range.Start`计算，确保坐标在段落内 |
| 14 | 简报表格无法提取 | docx/pdf表格在纯文本提取中丢失 | 后期人工整理；附件表格单独处理 |
| 15 | 上下文超限 | 本次会话轮次过多 | 核心产出已保存，下个会话用新对话继续 |
| 16 | python-docx标题缩进去不掉 | `pf.first_line_indent=Pt(0)` 设置后仍无效，Word继承Normal样式的`firstLineChars`属性 | 同时清除XML层级缩进：找到`pPr/w:ind`节点，移除`firstLineChars`属性，若ind为空则删除该节点 |
| 17 | `---` 被转为分页符 | md分页符不适合公文格式 | 脚本中跳过 `---`，不做任何处理 |
| 18 | 二级标题字体 | `### （一）xx` → 楷体加黑，易遗漏字体设置 | 始终显式设置楷体+加黑，不可依赖默认字体 |
| 19 | 单倍行距偏紧 | 单倍行距在 A4 公文排版中偏紧，字体贴近行边 | 改为固定值30磅：`line_spacing_rule=3`, `line_spacing=Pt(30)` |

## 五、写作经验

### `**` 标记使用原则
- `**N.xxx：**正文` → 编号前缀加黑，正文正常（可用）
- `**N.xxx**` 独立行 → 整段加黑（可用）
- `**标题。**` 无后续正文 → **忌用**，直接写正文不加星号

### 写作风格
- 每段5-6行，数字具体化（6.65亿而非数亿）
- 经验→对策 一一对应，动词开头（推进/加快/锁定）

## 六、脚本位置与用法

**md → docx：** `tools/md2docx.py`
**docx → md：** `tools/docx2md.py`

**用法：**
```powershell
# md → docx
C:\ProgramData\anaconda3\python.exe tools\md2docx.py 输入文件.md [输出文件.docx]

# docx → md（保留格式层级，可回排）
C:\ProgramData\anaconda3\python.exe tools\docx2md.py 输入文件.docx [输出文件.md]
```
- 不指定输出文件时，自动在同目录生成同名 .docx/.md
- 本机 Python 路径为 `C:\ProgramData\anaconda3\python.exe`（不能用 `python` 命令，会被 Windows 商店劫持）
- 生成 docx 前先关掉 Word（否则文件被占用报 PermissionError）

**草稿编写规范：** `tools/调研报告草稿规范.md`
