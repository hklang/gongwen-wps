# 干活入口

先看本文件，**只打开下面命中的 1～2 份**，不要五份全读。读完那 1～2 份再动手。

建议要短；有选项必须标一个「推荐」。

---

## 现在用户在干什么 → 去哪

| 用户在说 | 打开 | 不要 |
|----------|------|------|
| 新想法、做成什么样、有好几种做法 | `想构思.md` → 确认后再 `记方案.md` | 直接写代码 |
| 方案怎么记、开不开文、进度/已定 | `记方案.md` | |
| 改代码、加功能、修 bug | 小修补：`写代码.md` → `做测试.md`；新能力/改旧约定：先 `想构思.md` + `记方案.md` | 写完就说完成 |
| 写完了、好了吗、验收 | `做测试.md` | 跳过测去提交 |
| 提交、commit、push | `做测试.md`（过了没）→ `推版本.md` | 没证据就 push |

完整新能力默认顺序：`想构思` → `记方案` → `写代码` → `做测试` → `推版本`。  
单点 bug / 文案：`写代码` → `做测试`（回复里写清改什么、怎么验）。

---

## 五份各管什么（不必细读）

| 文件 | 一句话 |
|------|--------|
| `想构思.md` | 对标、边界、做成什么样 |
| `记方案.md` | 想清记清；验收条可扫 |
| `写代码.md` | 改对文件、改少 |
| `做测试.md` | 证明做没做到 |
| `推版本.md` | 测过了才交 |

---

## 总要求（默认不看）

只有这些才打开 `总要求/`，只取原则、忽略示例：

- 新模块怎么分层、模块怎么通信
- 新依赖该不该引
- 体积超标怎么拆
- 语言级错误处理、测试目录怎么建
