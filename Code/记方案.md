# 记方案

先看 `总.md` 确认该打开本文件。

方案没想清、没记清，禁止开写。对标见 `想构思.md`。

---

## 1. 只进一处，一题一文

| | 约定 |
|--|------|
| **目录** | 仓库里已有的那一处规格/方案目录；没有就建一处，只用这一处。禁止另开第二套 |
| **文件名** | `YYYY-MM-DD-序号-主题短名.md`（同日 01 起） |
| **一题一文** | 同一问题只维护这一份；禁止 `-v2` / `-最终` / `-副本` |
| **再研究** | **改原文件**；文首「修订」追加一行；**不改文件名** |
| **新建前** | 先搜同主题；有就改它 |

文首三行：`日期` / `状态` / `修订`。

---

## 2. 何时必须开文 / 何时不必

| 必须开文（或改原文） | 不必新开 |
|----------------------|----------|
| 新能力、新交互 | 单点 bug、文案 |
| 改旧约定、跨模块 | 已有规格里的小修补（改原文件对应栏） |
| 有选项要拍板 | 纯重构且行为不变（推版本说明里写清） |

不必开文时，仍要在回复里写清：**改什么、怎么验**。

---

## 3. 规格里必须能扫到

| 栏 | 写什么 |
|----|--------|
| **已定** | 拍过板、可验收的约定 |
| **验收** | 3～7 条可点、可复现；含失败时怎样。没有这一栏等于没想清 |
| **已完成** | 已落地、对照验收点过的 |
| **未完成** | 还没做，或做了一半 |
| **存疑** | 未拍板 / 行为不稳定 / 待核实 |
| **非目标** | 明确不做 |
| **模型建议** | 短；有选项必带「推荐」 |

状态：`已定` / `进行中` / `已完成` / `存疑` / `不做`。  
空栏写「无」，不要省略。

验收条写法：用户动作 → 可见结果。禁止「体验更好」「应该没问题」。

---

## 4. 怎么记

- 短句、表格式；禁止长篇复述聊天
- 改结论改同一份，别只活在对话里
- 与代码不一致：先改规格或标存疑，禁止默默分叉
- 文件级落点写在规格里，不写在 `想构思.md`

回答用户：先结论或「推荐」；进度三行（已完成 / 未完成 / 存疑）；细节指向规格文件。

---

## 5. 何时可以写代码

- [ ] 推荐已获同意（或用户明确「你定」）
- [ ] 必须开文的，已写入对应规格（含**验收**栏）
- [ ] 不必开文的，回复里已有怎么验
- [ ] 已通读 `写代码.md`

写完后必须过 `做测试.md`。测完才能按 `推版本.md` 交。
