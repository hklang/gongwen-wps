# 做测试

先看 `总.md` 确认该打开本文件。

写完代码先过本文件，再谈完成、再谈 `推版本.md`。  
**没有新鲜证据，不许说通过、修好、没影响。**

测什么：规格「验收」栏（或本轮怎么验）+ 写代码时抄下的回归锚。没验收条就先补再测。

---

## 1. 必须覆盖

| 层 | 测什么 |
|----|--------|
| 新行为 | 验收条逐条：动作 → 可见结果 |
| 旧路径 | 回归锚至少 3 条仍可用 |
| 失败 | 出错时不崩、有提示或可恢复，不把坏状态留下 |
| 契约 | 改过的接口 / 数据形状，调用双方都对过 |

漏一层 = 没测完。

## 2. 怎么测

| 类型 | 怎么做 |
|------|--------|
| 能跑的 | **当场跑**命令或已有测试。看完整输出和退出码。上次跑过不算 |
| 不好自动测的 | **点验清单**：步骤 + 期望。自己能做的先做；要人点的单独标出 |
| 修 bug | 先复现，再改，再跑同一条证明没了 |

测试输出进仓库约定的临时目录，不要散落。

## 3. 怎么回报

回复里固定三块，短句即可：

- **过了**：哪几条，凭什么（命令摘要 / 点了哪一步）
- **要人点**：哪几条、怎么点、期望是什么
- **没过**：哪条坏了 → 先修，再从本文件重来。禁止带着红的去推版本

禁止：「应该没问题」「感觉好了」「逻辑上不会坏」。

## 4. 和另外几份的分工

| 文件 | 不管测 |
|------|--------|
| `记方案.md` | 只写验收条（测什么） |
| `写代码.md` | 只改代码；抄回归锚 |
| **本文件** | 证明做没做到 |
| `推版本.md` | 本文件过了才交 |

## 何时去看总要求（可跳过）

默认不看。仅当：要补测试目录/命名、集成怎么搭、覆盖率怎么看。  
读 `总要求/代码约束.md` 测试相关节，只取原则。
