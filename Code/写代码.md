# 写代码

先看 `总.md` 确认该打开本文件。

动手前通读本文件。规格没记清先看 `记方案.md`。  
写完不要在这里声称完成，立刻去 `做测试.md`。

日常默认（不必去总要求）：函数 ≤100 行；文件 ≤200KB；超标先拆再加。命名跟旁边已有文件走。

---

## 1. 先找，再写

- 先搜：这个能力是否已经存在
- 有就改它，不要新建
- 确实要新建：先说明原因，等确认
- 不顺手重构，不加「以后可能用到的」，不加无意义注释

## 2. 改对层

| 你要做的 | 落在 |
|----------|------|
| 展示、输入、路由 | 界面 / 入口 |
| 业务判断、状态流转 | 业务逻辑 |
| 读写、外部调用 | 数据 / 适配 |
| 可调数值、密钥、开关 | 配置入口（唯一） |

不要为了「干净」另起炉灶。密钥、地址、端口禁止硬编码。  
契约先于实现：接口 / 数据形状有变，先改调用双方。

## 3. 动手前：会碰到谁

把**同一条用户路径**搜全，列出被带着走的文件。

- 从规格「已定」抄 **至少 3 条**旧能力，交给 `做测试.md` 当回归锚（无规格则从现有行为抄）
- 新想法 → **停**，记进存疑
- 改旧约定 → 先说出来

临时产物进仓库约定的临时目录（须已 gitignore），不要散落。

## 4. 安全（日常）

- 禁止把用户输入拼进 SQL / 命令 / 模板
- 生产用正式日志，不用调试打印

---

## 何时去看总要求（可跳过）

默认不看。仅当：新模块分层、模块通信、新依赖该不该引、超标怎么拆、语言级错误处理。  
`总要求/代码约束.md` · `总要求/架构设计规范.md`，只取原则。

写完 → `做测试.md`。
