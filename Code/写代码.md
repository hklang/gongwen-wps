# 写 Code 前 Checklist

**给建议要简明扼要，别啰嗦；有选项时必须标一个「推荐」。**

## 1. 先找，再写

- 用 Grep/Glob 搜一下，这个功能/路由/类**是否已经存在**
- 有就改它，不要新建
- 确实要新建，先说明原因，等确认

## 2. 确认改的是正确的文件

- 路由 → `__main__.py`，配置 → `settings.py`，DB → `db.py`
- 不要在错误的文件里加代码
- 不要为了"干净"另起炉灶重写

## 3. 只做要求的，不多不少

- 不顺手重构，不加"以后可能用到的"功能
- 不加无意义注释，不写 `# TODO`、`# 临时`
- 单个函数不超过 100 行，文件不超过 200KB

## 4. 临时文件统一放 temp/

- 调试脚本、截图、中间结果、日志、测试输出 → 全放根目录 `temp/`
- 代码里写路径时用 `ROOT/temp/xxx`，不要散落到项目各处
- `temp/` 已加入 .gitignore，内容不会进 git

## 5. 配置/密钥不能硬编码

- Key、IP、密码、端口 → 统一写 `engine/settings.py`

## 6. 改了接口前后端一起改

- 改了 API 路由 → 对应 HTML 同步改
- 改了 DB 表结构 → `db.py` 的 migrate 同步改

## 7. 安全

- 禁止 SQL 拼接，必须参数化
- 禁止用户输入直接拼接到命令/模板
- 生产代码用 `logging`，不用 `print()`

---

## 什么时候去看总要求

> 总要求在根目录 `总要求/` 下，有两个文件：`代码约束.md` 和 `架构设计规范.md`

**去看 `代码约束.md`**，当你要：
- 新建文件，不确定命名格式（snake_case？PascalCase？）
- 不确定函数/文件行数是否超标
- 需要引入新的第三方库，评估是否合适

**去看 `架构设计规范.md`**，当你要：
- 新增一个模块，不确定放哪一层（展示层/服务层/数据层）
- 两个模块之间需要通信，不确定用直接调用还是事件
- 感觉代码耦合变重了，需要拆解思路
