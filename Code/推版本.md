# 推 Git 前 Checklist

**给建议要简明扼要，别啰嗦；有选项时必须标一个「推荐」。**

## 1. 理清本轮改了什么

- 本轮核心改动是什么？一句话说清楚
- 有没有影响其他模块的全局变更（如 settings.py、db.py、base_page.py）
- 有没有新增/删除/重命名文件

## 2. 更新 README / 文档

- `engine/README.md` — 新功能、新命令、新配置项要补上
- `CLAUDE.md` — 架构有变化时更新（新文件职责、新 API、流程改变）
- 如果改了 `settings.py` 的配置项，在 README 里同步说明

## 3. 清理垃圾文件

```bash
# 检查有没有遗留的测试文件、临时脚本
git status

# 常见垃圾：
# - test_xxx.py / debug_xxx.py 临时脚本
# - *.log / *.bak / *.tmp
# - __pycache__ 没被 gitignore 的
# - 空文件夹
```

**清空 temp/**（根目录临时文件统一放这里，推 git 前清掉）：

```bash
rm -rf temp/* && echo "temp cleared"
```

## 4. 去重检查（删前先问我）

列出可疑文件后，**不要自己决定删**，先告诉我，确认后再删。

- 同一功能有没有出现两个文件？（本轮新建的文件和旧文件是否重叠）
- 有没有被废弃但没删的旧文件？（没有任何地方 import 它）
- 同一个 API 路由有没有出现两处定义？
- `pages/` 里有没有重复的站点脚本（同域名两个文件）
- 配置值有没有还在多处硬编码的（应该统一在 `settings.py`）

```bash
# 快速查重复站点脚本
ls Project/pages/ | sed 's/_page.py//' | sort | uniq -d

# 查有没有同名函数定义在多个文件
grep -rn "^def foo\|^class Foo" Project/engine --include="*.py"
```

## 5. Commit message 写清楚

```bash
git add Project/engine/settings.py Project/engine/...  # 按模块加，别 git add -A
git commit -m "feat: 一句话说核心改动"
```

格式：`feat / fix / refactor / chore: 做了什么`

## 6. 推送

```bash
git push
```

如果要同步到服务器：

```bash
python gitpush.py "commit message"
```

## 快速自查问题清单

| 问 | 答 |
|----|-----|
| settings.py 改了吗？ | README 同步了吗？ |
| 新增了文件吗？ | CLAUDE.md 架构部分更新了吗？ |
| 删了什么吗？ | 有没有其他文件还在 import 它？ |
| 改了数据库结构吗？ | db.py 的 migrate 函数更新了吗？ |
| 改了 API 路由吗？ | 前端 HTML 对应调用也改了吗？ |
