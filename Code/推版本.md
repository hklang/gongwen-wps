# 推版本

先看 `总.md` 确认该打开本文件。

没过 `做测试.md`，禁止提交。没让交的文件不要加。

---

## 1. 交之前的门

- [ ] 已按 `做测试.md` 测完；回复里有「过了 / 要人点 / 没过」
- [ ] 没过的已经修掉并重测
- [ ] 核心改动能一句话说清

## 2. 理清本轮

- 有没有全局变更（配置、数据形状、公共基类、接口）
- 有没有新增 / 删除 / 重命名
- 入口文档、配置说明：行为变了就改

## 3. 不提交垃圾

先看工作区。不该进库：调试脚本、一次性文件、日志、备份、缓存、密钥、本机路径、个人笔记。  
临时目录清空内容（目录保留）。

## 4. 去重（删前先问）

同一功能双文件、无引用的废弃文件、同一接口两处定义、配置多处硬编码 → 先列出，确认再删。

## 5. 按意图提交

- 一次一个意图；夹带的先拆开
- 按模块 add，禁止 `git add -A`
- `feat` / `fix` / `refactor` / `chore` / `docs`：一句话核心改动
- 确认当前分支再 push；未要求不要 force push，不要改 git config

## 快速自查

| 问 | 答 |
|----|-----|
| 测过了吗？ | 回复里有 `做测试.md` 那三块 |
| 旧能力还在吗？ | 回归做过 |
| 配置/接口/数据形状改了吗？ | 文档和调用方同步了 |
| 删了文件吗？ | 没有残留引用 |
| 临时文件、密钥在暂存区吗？ | 拿掉 |
