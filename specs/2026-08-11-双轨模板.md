# 双轨模板（官方一份 · 我的云端）

> 2026-08-11 · 已定案 · **S2b 已实现**（v169 / 扩展 0.3.41）  
> 对标：WPS「系统模板 + 我的模板」；不做另存、不做网盘。

## 产品句

- **官方模板**：云端只一份，管理员随时改；用户始终跟母版（只读选用）。  
- **我的模板**：用户自建，存在**该用户云端库**；可增删改。  
- **不做**「从官方另存为我的」——要改官方内容，用户自己复制粘贴到「我的」里再改。  
- **正文稿 / 素材 / 工程**仍只在本机；云端只存短骨架，有上限。

## 侧栏（模板区）

两块即可，别再叠第三态：

1. **官方** — 按文种浏览 / 预览 / 选用（落到本机工程再写，或仅引用）  
2. **我的** — 列表 + 新建/编辑/删除（云端 CRUD）

## 行为

| 动作 | 官方 | 我的 |
|------|------|------|
| 管理员改母版 | 用户下次拉取即新内容 | 不影响 |
| 用户改正文 | 不允许 | 允许 |
| 从官方→我的 | **不提供按钮**；用户自行复制粘贴 | — |
| 跨设备 | 跟账号走（读官方） | 跟账号走（读本人库） |

## 上限（防当网盘）

- 每户「我的」模板：建议 ≤ 50 篇  
- 单篇 body：建议 ≤ 32KB（约一万汉字量级封顶，实现时可再调）  
- 禁止存附件/二进制；仅 md 文本  

## 数据（实现时）

- 官方：现有 `templates` 表（全局，无 `user_id`）  
- 我的：新建 `user_templates`（`user_id, code/id, title, category_code?, body_md, updated_at`）  
- API 草案：`GET/POST/PATCH/DELETE /api/user/templates`（需登录短票）  
- Admin 只动官方，看不见/改不了用户「我的」正文（除非将来合规审计另定）

## 明确不做

- 官方 → 我的「另存」  
- 用户模板回写官方  
- 云端「我的文稿」库  
- 复杂版本 diff / 强制覆盖本机缓存流程（官方以云为准即可）

## 与旧说法的关系

商业化总方案曾写「用户自建模板默认只存本机」。  
**本文件为准**：自建改走用户云端库；本机工程里的 `模板/` 仍可作落地缓存，但不作为「我的」权威源。
