# 撰写正文稿落稿（对话 / 正文分离）

## 定调

- **对话区**：只聊说明，不直接改文档。  
- **正文稿区**：单独展示 `edit.md` 草稿；用户点按钮才写入。  
- **人机双写优势**：字进 WPS 正文，且每次写入可回滚。

## 落稿三按钮

| 按钮 | 行为 |
|------|------|
| **整篇排版写入** | 确认后：先存版本 → 按「一、／（一）」等分层套样式 → **覆盖当前全文** |
| **写入光标处** | 先存版本 → 在光标处插入草稿（跟上下文段落格式，尽量不剥样式） |
| **覆盖选定区** | 先存版本 → 替换当前划选（无选区则禁用并提示） |

另：**复制**（不写文档、可不存版本）。

## 版本铁律（用户拍板）

- **每一个会改正文的点击**（整篇 / 光标 / 选定）都必须先 `saveActiveToVersion()` 成功，再写入。  
- 存版本失败 → **中止写入**，提示原因（未保存/无工程根等）。  
- **清空对话**、收起草稿：**绝不**改正文、不存版本。

## 与对话的关系

不再区分「仅对话 / 授权改稿」。  
撰写一律可返回正文稿；**是否写入文件只由用户点正文稿区按钮决定。**  
纯讨论时模型可不返回 `edit.md`。

## 不满意怎么重来

正文稿可多轮替换；未点按钮则文档不变。点过后用「版本」里刚存的快照恢复，或 Ctrl+Z。

## 精修

认稿后的局部多方案润色仍走精修；撰写「覆盖选定区」供初稿阶段用户操作落点。

## 实现要点

- `GwProject.saveActiveToVersion` 为落稿前置  
- 禁止无版本保护的 `Content.Text` 整篇覆盖  
- 整篇写入：分段插入 + 样式名尝试（标题 1/2/3、Heading、正文）  
- UI：`aiDraftPanel` 独立于聊天气泡
