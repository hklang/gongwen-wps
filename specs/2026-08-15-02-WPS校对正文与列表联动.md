## 研究（2026-08-16，默认选中 / 左右联动）

对照：spike `findAndHighlight`、官方 `Selection` / `ShowDialog`、本机已试路径。

### 拆开：什么已通、什么不通

| | 状态 | 依据 |
|--|------|------|
| 点正文 → 右侧跟条 | **通** | 你已确认。焦点在文档窗，系统选区本身就在，250ms 轮询对段 |
| 点右侧 → Find 把 Selection 设到那几个字 | **通（逻辑）** | 与 spike 同一套 `HomeKey(6)+Find.Execute`；采纳能改对，说明选区在 |
| 校对结束右侧第 1 条 `.on` | **通** | `proofActive=0` 后 `renderOpts` |
| 点右侧 / 默认 → **看见正文蓝选** | **不通** | 焦点在 `ShowDialog`，文档窗格不是活动窗格，WPS 不画选区 |
| 涂黄当「看见」 | **曾通，已停** | 黄能看见；`Shading=0` 在 WPS 是黑色；关窗 JS 经常不跑，脏稿要手清 |

spike 也是 `ShowDialog` + 同一段 Find，且注释写明「只定位选区，不涂色」。当时「能选中」更像是：选区被设上了（采纳有效），或点完后焦点回到了文档才看见蓝选——**不是**助手一直在前时正文会反蓝。

### 根因（不是漏写 Select）

1. 官方：整个应用只有一个活动 `Selection`，属于**活动文档窗格**。  
2. 官方 demo 自己写了：改 `Range.Text` 才触发重绘，不能用来「只选中」。  
3. 助手是 **非模态** `ShowDialog(..., false)`，所以能点正文（左→右才成立）；点右侧时焦点仍在对话框。  
4. `TaskPane` 停靠同一窗口才能边开助手边画蓝选；WPS 12.1.0.26895+ 挡 Ribbon，**已否**。  
5. `Activate` / `SetForegroundWindow`：要么冲掉选区，要么把助手压到文档后面。

**三选二仍成立：** 独立窗 + 绝不改格式 + 助手在前看见定位 → 做不到。

### 「默认选中」应拆成三条验收

| 条 | 含义 | 现状 |
|----|------|------|
| 1 | 右侧第 1 条亮 `.on` | 已有 |
| 2 | 正文滚到第 1 处附近 | Find + `ScrollIntoView` 已有 |
| 3 | 正文里能看出是哪几个字（蓝选或标记） | 助手在前时 **没有** |

你要的若是第 3 条，继续堆 Select 无效。
