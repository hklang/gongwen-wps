## 一句话

点右侧要在正文里看见那一处；点正文，右侧跟到那一条。

## 对标

| 产品 | 学什么 | 我们做不到的 |
|------|--------|--------------|
| **Word 审阅窗格** | 点条定位、列表跟光标 | 窗格**停靠在同一窗口**，正文始终能画系统选区 |
| **Grammarly / WPS 校对** | 当前问题在文中有标记 | 文中常驻一堆波浪线（脏、和用户底色打架） |

助手已定是 **ShowDialog 独立窗**（`2026-08-11-07`：TaskPane 挡 Ribbon，禁止）。焦点在助手时，WPS **不画**文档里的系统选区——这是窗体模型，不是漏写一行 Select。

## 已定（仍有效）

| 方向 | 行为 |
|------|------|
| 左 → 右 | 点正文该段 → 右侧最近条 `.on`（已通） |
| 重复句 / 另处 | 第 n 次，不搜第一次 |
| 采纳 | 替换该 Range；平移其余坐标 |
| 清空 / 切走校对 | 停轮询；**文中不留标记** |
| 选区校对 | 相对当次划选 |
| 布局 | 独立窗；不改回 TaskPane |
| 中转 | `proofread.py` 不动 |

## 已试不通（不再堆 Select）

| 试过 | 结果 |
|------|------|
| `Range.Select` / `SetRange` / `Find.Execute` | 焦点在助手时正文无反选 |
| 先 Activate 再选、选完再 Activate | 冲掉选区或助手抢回焦点，仍看不见 |
| `SetForegroundWindow` 把文档提到前台 | 用户仍反馈左侧不能选中；且会把助手压到后面 |

官方 demo 靠 **改 Range.Text** 才重绘，不能用来「只选中」。

**三选二（此前没说破）：** 独立窗 + 绝不改格式 + 看见定位 → 做不到。Word 用停靠换「不改格式也能看见选区」；我们停靠已否。

## 选项（拍板后再写）

| | 做法 | 利 | 弊 |
|--|------|----|----|
| **A 推荐** | **只给当前条**打浅底纹（或浅下划线）。换条/采纳/清空/切走校对立刻还原。不是全文涂黄。 | 助手在前也能看见；对标审阅「当前处」；不抢焦点 | 当前处短暂改格式，必须保证清干净 |

| D | 继续调 Select/Activate | — | 已试多次，判定此路停 |

**推荐 A。** 左→右保持现网。撰写/精修不套。

### A 的验收边界

- 点右侧第 n 条：正文滚到该处，**仅该 span** 有浅底；其它处无标记
- 再点另一条：旧底去掉，新处打上
- 采纳 / 忽略后该条：底去掉
- 清空或离开校对 Tab：全文无校对底纹
- 不插批注；不给所有错误同时涂色
