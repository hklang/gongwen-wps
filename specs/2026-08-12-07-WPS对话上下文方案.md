> 日期：2026-08-12  
> 状态：**商用终局规格**（架构一次定准；实现可分期，但不得用「临时糊层」破坏终局模型）  
> 关联：`specs/2026-08-12-01-WPS对话工具环与素材索引.md` §6.5、`specs/2026-08-12-08-WPS写作聪明程度方案.md`（质量/比肩大笔杆子）、`Code/想构思.md`、`Code/总要求/架构设计规范.md`  
> 产品目标：右侧对话像 **Cursor 续聊**——用户想到哪说到哪，系统按**本轮意图**选对上下文，稳定、可观测、可计费可控。

## 0. 商用要解决什么

不是「多塞一点 history」，而是一张可售卖的能力：

| 商用诉求 | 终局要求 |
|----------|----------|
| 写得对 | **焦点跟本轮意图走**：抠标题就不被全文拽走；写冒段就不被最近标题锁死 |
| 稳 | 同输入同策略可复现；失败可解释、可重试 |
| 快 | 默认 **一轮出稿**；仅低把握才澄清（不加默认分析税） |
| 省 | token 有硬预算与裁切顺序；软修剪减少垃圾轮 |
| 可运营 | 每轮上下文决策可打日志；支持客服/研发定位「为啥写偏了」 |
| 普惠 | 不写死文种/单位/项目名；专名来自用户话与精读材料 |

**非目标（明确不做进终局主路径）**

- 每轮强制「先分析会再出稿」双模型税  
- 整夹素材预塞冒充智能  
- 用本地模板顶替模型结论

## 1. 定调

**焦点跟本轮意图走。**

| 本轮要干啥 | 抬哪一层 |
|------------|----------|
| 研究/改最近标题 | **L3 底稿/钉住**；L1 在场不抢戏 |
| 冒段/开篇/总起 | **L1 全文框架**；L3 仅目录摘要 |
| 改架构 | **本轮用户话**；旧底稿对照不锁死 |
| 某节正文 | **钉住 > L1**；全局底稿次之 |
| 低把握短句 | **先澄清**，再出稿 |

继承前文 = 「任务还在」，≠ 「永远用全文盖住当前焦点」。

## 2. 终局架构：Context Kernel（上下文内核）

在加载项内形成明确模块边界（可先落在 `taskpane.js`，体积上来再拆文件），对标分层：展示 → 服务 → 状态。

```
┌─ UI（对话气泡 / tip / 可选澄清条）─────────────────────┐
│  只展示用户可见消息；不展示技术块                         │
├─ Context Kernel（本方案核心）───────────────────────────┤
│  IntentEngine → TaskCardStore → HistoryPruner           │
│  → LayerAssembler → BudgetCutter → PromptBuilder        │
├─ Chat / ToolLoop / Relay ───────────────────────────────┤
│  只消费 Kernel 产出的 message + session_summary 等       │
├─ Persistence（GwUserPrefs / 工程 .gongwen 可选）─────────┤
│  chatSnapshot + taskCard + baseDraft + readSet          │
└─────────────────────────────────────────────────────────┘
```

**铁律**：组装上下文只走 Kernel；禁止各处手搓拼接导致权重漂移。

### 2.1 单轮数据流（默认商用路径）

```
用户发送
  → IntentEngine.classify（规则 + 置信度）
  → 若 confidence < 阈值 或 信号冲突 → Clarifier（不出稿）→ 等用户一句 → 回到 classify
  → 否则 LayerAssembler 按意图选层
  → BudgetCutter 按硬顺序裁到预算内
  → PromptBuilder 生成 sendMsg（气泡仍只用用户原文）
  → ChatLoop / Relay 出稿
  → 回写：更新 TaskCard（仅用户侧事实）、baseDraft、readSet
  → ContextTrace 打日志（可 GwLog）
```

## 3. 四层模型（终局字段）

注入时必须带**层标签**，禁止糊成一锅无主次的长文。

| 层 | 名称 | 终局内容 | 谁可写 |
|----|------|----------|--------|
| L1 | Task Card | 结构化任务说明书 | 仅用户消息/澄清确认 |
| L2 | Session | 修剪后 history、纠正、read_set 元数据 | Kernel |
| L3 | Focus | 钉住、baseDraft、doc_md 摘要、点选层级 | 宿主状态 |
| L4 | Evidence | tool_results / @ 精读 | 工具环 |

### 3.1 Task Card Schema（商用必定）

```json
{
  "v": 1,
  "updatedAt": 0,
  "sourceMsgIds": [],
  "occasion": "",
  "deadline": "",
  "lengthLimit": "",
  "scope": "",
  "framework": [{ "id": "1", "title": "", "bullets": [] }],
  "style": { "parallel": true, "notes": "" },
  "corrections": [{ "at": 0, "text": "" }],
  "rawPins": []
}
```

| 字段 | 含义 | 更新规则 |
|------|------|----------|
| `occasion` / `deadline` / `lengthLimit` | 通知里的场合、时限、字数 | 新通知覆盖旧 |
| `scope` | 分管/负责范围 | 用户改口覆盖 |
| `framework[]` | 全文第 N 点 | **整卡替换或按点 id 覆盖**；禁止把「某一节临时标题探索」写入 |
| `style` | 对仗等偏好 | 合并；冲突取最新 |
| `corrections[]` | 最近纠正（有上限，如 5） | 追加；过旧进修剪 |
| `rawPins[]` | 过渡期：未结构化的关键用户原句（≤3 段） | 有 schema 字段后降级为备份 |

**禁止写入 Task Card**：助手 options/edit 全文、精修方案、失败提示。那些是 L3/过程。

**抽取策略（终局）**

1. **M1**：关键词命中的用户段落入 `rawPins` + 粗提 `framework`（正则「第N点」）。  
2. **M2**：在出稿成功后的空闲或下轮发送前，用**一次轻量结构化**（可同一模型、强制 JSON、禁止写稿）把 `rawPins` 升格为 schema；失败则保持 rawPins。  
3. **M3**：用户可在设置/弱入口「查看已记任务」只读（加厚可编辑）。

注意：M2 的结构化 **≠** 默认分析轮；它更新的是持久 Task Card，不挡本轮出稿关键路径（可异步）。若与本轮强相关且卡为空，允许发送前同步一次（有超时降级）。

### 3.2 Focus 描述符

```json
{
  "pin": { "text": "", "heading": "" },
  "baseDraft": { "mi": 0, "vi": 0, "kind": "outline|body|lead|mixed", "md": "", "toc": [] },
  "docDigest": { "headings": [], "chars": 0 },
  "levels": ["h1", "h2"]
}
```

`kind` 由底稿形态推断：多行标题少段落 → `outline`；有冒段结构 → `lead` 等。供 Intent 与 Assembler 使用。

## 4. IntentEngine（意图引擎）

### 4.1 标签集（稳定枚举）

`lead` | `outline` | `revise_outline` | `body` | `suite` | `chat` | `clarify_reply` | `ambiguous`

### 4.2 分类输入

- 本轮用户原文、点选层级、是否勾选出结论/给多份  
- 是否有 pin / baseDraft及其 `kind`  
- Task Card 是否非空  
- 上一轮意图（短记忆）  

### 4.3 规则分与置信度（商用可测）

每条规则加减分，归一到 `confidence ∈ [0,1]`。

| 信号 | 倾向 |
|------|------|
| 含 冒段/开篇/开头/总起 | `lead` + |
| 含 改成/不要…要…/换架构/「甲：乙：」 | `revise_outline` + |
| 点选 h1/h2/h3 且非 lead 词 | `outline` + |
| 点选 body / 充填该节 | `body` + |
| 精修 tab | `suite`（走精修组装器） |
| 未勾出结论 | `chat` |
| 原文极短（&lt;12 字）且 L1 与 L3 都非空 | `ambiguous` 倾向 + |
| 同时强命中 lead 词与「只改这组标题」 | 冲突 → `ambiguous` |

**阈值（默认，可配置）**

- `confidence ≥ 0.72`：直接出稿  
- `0.45 ≤ confidence < 0.72`：出稿，但 Prompt 加强「自对齐」句；日志标 `soft`  
- `&lt; 0.45` 或显式冲突：走 Clarifier  

### 4.4 澄清协议（Clarifier）

**触发**：低置信 / 多标签打架 / 用户话无法判断焦点。

**形态（商用默认）**：宿主生成 **两条可选确认**（不强制再调模型），例如：

- 「A. 统领全文写冒段」  
- 「B. 只打磨当前这组标题」  

用户点选或回「A/B/…」→ `clarify_reply` → 带上选定意图强制出稿。

**降级**：无 UI 按钮时，助手气泡只发确认问句、`allow_edit=false`；用户下一句当作澄清。

**禁止**：澄清轮输出 options/edit 长稿。

### 4.5 同轮自对齐（高置信出稿仍保留）

静默要求模型用**一句**确认焦点后再写 JSON。宿主 Assembler 已按意图调层；自对齐是双保险，不是主判决。

## 5. 按意图的权重矩阵（Assembler）

**总闸门**：本轮用户明示 ≥ 一切旧产物。

| 意图 | 高 → 低 |
|------|---------|
| `outline` | 本轮话 ≥ **L3 底稿/钉住** ≥ L1（防跑出全文）≥ L2 ≥ L4 |
| `revise_outline` | 本轮话 ≥ L1（更新后）≥ L3 旧底稿对照 ≥ … |
| `lead` | 本轮话 ≥ **L1** ≥ L3 **toc 摘要**（禁底稿全文抢戏）≥ … |
| `body` | 本轮话 ≥ 钉住 ≥ L1 ≥ 全局底稿 ≥ … |
| `suite` | 钉住原文 + 精修要求 ≥ 材料精读 ≥ Task Card 短摘要 |
| `chat` | 短 L1 + 修剪 history；不附底稿 |

注入时写清【本轮焦点说明】一行，例如：`本轮=lead；须统领 Task Card 框架；底稿仅作目录。`

## 6. Token 预算与硬裁切（BudgetCutter）

### 6.1 默认预算（可配置）

以「出稿用户消息总长」计（不含系统提示）：

| 档 | 总预算（字符，中文约等） | 场景 |
|----|--------------------------|------|
| fast | 12_000 | 默认 |
| standard | 20_000 | 增强 |
| max | 32_000 | 显式长文 |

### 6.2 裁切顺序（超预算时严格按此砍）

1. 旧助手长 md / 已替代结论（L2）  
2. `doc_md` 正文（保留标题目录）  
3. L3 底稿全文 → 改为 toc  
4. L4 精读中最早/最低相关篇（保留 read_set 路径）  
5. L2 history 再缩短轮数  
6. **最后才动** L1 Task Card 与本轮用户原文（本轮原文不裁）  

日志记录 `cutSteps[]`。

## 7. 双源冲突：对话任务 vs 正文现状

| 情况 | 策略 |
|------|------|
| Task Card 有框架，doc 标题不一致 | **出稿类**：以本轮意图为准——`outline/lead` 尊 Task Card + 本轮话；若用户说「按正文现有标题」则抬 `docDigest` |
| 用户只在 Word 里改、对话未说 | 不自动改 Task Card；下轮 `docDigest` 进入 L3；若与 Card 冲突且意图模糊 → Clarifier |
| 精修只钉一节 | 不改 Task Card 框架 |

商用原则：**对话是意图源，正文是落点与现状**；二者冲突要显式策略，禁止默默听随机一层。

---

## 8. 撰写 vs 精修

| Tab | Kernel 行为 |
|-----|-------------|
| 撰写 | 全套意图矩阵；出结论/给多份走 Chat |
| 精修 | 意图固定偏 `suite`；Task Card 只作短摘要防跑题；主上下文=钉住+要求+材料 |
| 校对 | 不走撰写 Kernel 组装（保持现校对链路） |

---

## 9. History 软修剪（商用默认开）

目标：请求体干净；UI 默认可保留回放（硬删为加厚）。

**可剪**：失败轮、宿主元提示、已被替代的旧 options 全文、寒暄、助手超长 md（改成短摘要）。  
**必留或进卡**：立任务句 → Task Card；近 2～4 轮用户原话；纠正句。  

参数默认：有效 history 8～12 轮；助手单条 ≤ 1000 字。

硬删气泡 /「精简对话」：M2+；精简不得清 Task Card。

## 11. 可观测性（商用必备）

每轮 `ContextTrace`（接 `GwLog`，tip 双击可拷）：

```json
{
  "intent": "lead",
  "confidence": 0.81,
  "layers": ["L1", "L3toc", "L2"],
  "baseDraftKind": "outline",
  "cuts": [],
  "clarify": false,
  "msgChars": 0
}
```

客服/研发凭此判断「选错层」还是「模型未遵守」。  
**不上报用户正文到公网**（除非用户已登录中转且符合现有隐私策略）；本地环状日志默认。

### 11.1 状态条「本轮理解」（对标 Cursor 过程可见 · 对齐思考可见层）

- **学 DeepSeek 的「先想再写」，不学「长思考墙」**：对齐结论服务成稿与焦点；展示用短句。  
- 宿主根据 Intent + layers 拼一句短理解（C0）；演进见聪明程度方案 §0.1 / 路线 C（可加依据·参照摘要）。  
- 展示位：下方 `#aiTip` + 脚注 `#aiEditStatus`（如「冒段」「标题」）。  
- 发送中叠加进度：`理解：冒段 · … · 撰写中… / 查阅材料…`。  
- 澄清时：`理解：待确认 · 请回复 A 或 B`。  
- 写入 `GwLog`（`ctx.understand`），与 ContextTrace 对照；质量侧可并行 `quality.trace`。  
- **联合研究**：上下文里程碑与 `2026-08-12-08-WPS写作聪明程度方案.md` 共用评测任务（焦点分 + 质量分）。

## 12. 失败与降级

| 失败 | 降级 |
|------|------|
| Task Card 抽取失败 | 仅用 rawPins / sessionFramework 原文块 |
| 澄清用户不理，又点发送 | 沿用上一澄清选项或标 ambiguous 再问一次（最多 2 次），其后按 soft 出稿并打日志 |
| 预算裁切过猛 | 保本轮话 + L1；tip「上下文已压缩」 |
| 中转失败 | 现有失败气泡；不本地造稿 |

---

## 13. 与工具环 / 中转

- Kernel 产出的 `session_summary` = Task Card 渲染文本 + 本轮焦点说明。  
- 中转系统提示增加：必须遵守【本轮焦点说明】与分层标签；禁止把 L3 标题底稿当成全文主题（当焦点=lead）。  
- 给多份无 options：保持现有重试 1 次 + reply 捞组（已有）。

---

## 14. 安全与合规

- 普惠：宿主约束不写死单位/项目名。  
- 无精读不写数（现有）。  
- Task Card / 对话快照含工作内容：仅本机 prefs（或用户工程目录）；不进错误上报默认字段。  
- 清空对话必须清 Task Card，避免换稿串味。

## 15. 分期（同一终局，禁止分叉架构）

| 里程碑 | 交付 | 验收锚点 |
|--------|------|----------|
| **M1 商用可卖最小闭环** | Intent 规则+置信度；按意图组装 L1(rawPins)/L3；lead 底稿降权；history 软修剪；ContextTrace；澄清；状态条「本轮理解」 | U1–U3, U5, U7 |
| **M2 结构化与精修对齐** | Task Card schema 升格；异步/同步结构化；精修走 suite 组装；澄清双按钮；硬预算裁切 | Schema 稳定；U4；精修不跑题 |
| **M3 运营与体验加厚** | 只读任务卡；精简对话；可选 `.gongwen/task.json`；阈值可配置 | 运营可定位；跨会话工程记忆按加厚包 |

**约束**：M1 就使用四层标签与 Intent 枚举；禁止 M1 用「又一段 sessionFrameworkHint」冒充终局后又推翻。
