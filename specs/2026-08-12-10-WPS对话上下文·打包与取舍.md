# WPS 对话上下文 · 打包权与取舍权（补丁规格）

> 日期：2026-08-12  
> 状态：**已确认并落地**（宿主打包贴标签；模型取舍；出多份不自动 baseDraft）  
> 父规格：`specs/2026-08-12-07-WPS对话上下文方案.md`（四层 / Intent / 预算 / Trace **仍然有效**）  
> 关联：工具环、`写作聪明程度方案.md`、`Code/想构思.md`  
> 起因：换节写作串上一节结论、宿主用专名/关键词「隔离底稿」——违反普惠，也违背「判断交给模型」。

---

## 0. 一句话

**宿主负责「打包与贴标签」；模型负责「本轮要啥、不要啥」。**  
父规格的「焦点跟本轮意图走」仍然成立——意图只决定**怎么标权重、怎么裁长度**，不决定**语义上删哪段正文**。

---

## 1. 旧方案缺了什么（研究结论）

父规格已经定准：

| 已有 | 含义 |
|------|------|
| 四层 L1–L4 + 层标签 | 禁止糊成一锅 |
| Intent 枚举 + 权重矩阵 | 按意图抬层（如 lead 底稿改 toc） |
| BudgetCutter | 超长时按固定顺序砍 |
| 普惠 | 不写死单位/项目名 |
| 自对齐一句 | 模型用短句确认焦点 |

**缺口（今晚暴露）：**

1. **没写清「取舍权」在谁手里**  
   「Assembler 按意图选层」易被实现成：宿主按专名/关键词**删掉**某层正文。那是内容判决，不是打包。
2. **`baseDraft` 生命周期未钉死**  
   一出多份就自动当续改底稿 → 换节后旧节全文仍占 L3，模型被噪音淹没（不是模型笨，是包打错）。
3. **缺验收用例「换节不串味」**  
   U1–U9 有冒段/改架构，没有「写完 A 节再写 B 节」。
4. **与「一切交给模型判断」未对齐表述**  
   用户要的是：**语义取舍**交给模型；不是取消 Intent/分层（否则又回到整锅 history）。

## 2. 两条权（本补丁的核心）

```
┌─ 打包权 Pack（宿主 Context Kernel）─────────────────────┐
│  Intent → 决定「推荐权重 / 层标签 / 是否 toc 化」         │
│  Assembler → 按矩阵把各层打进包，层层带标签               │
│  BudgetCutter → 只按长度与固定顺序砍（机械）               │
│  禁止：按专名、段落标题相似度、业务关键词删语义内容         │
└──────────────────────────────────────────────────────────┘
                            ↓
┌─ 取舍权 Choose（模型）──────────────────────────────────┐
│  读标签标签 + 本轮用户话                                   │
│  决定：用钉住还是旧结论卡、要不要历史他段、读哪份材料       │
│  自对齐首句可声明「本轮采用：…；忽略：…」                   │
└──────────────────────────────────────────────────────────┘
```

| 动作 | 谁 | 举例 |
|------|----|------|
| 本轮是 body 还是 lead | 宿主 Intent（规则分，可测） | 点选正文 → 倾向 body |
| body 时钉住标签优先于底稿标签 | 宿主贴标签 / 排序提示 | 不删底稿，只标「钉住优先参考」 |
| 旧结论卡是否与本轮无关 | **模型** | 写 B 节时忽略 A 节结论全文 |
| 致远段是否写大冬会代建数 | **模型** + 精读材料 | 有材料则据实；无则勿搬 A 节政治专段 |
| 超长砍 history | 宿主 Budget | 机械 |

**铁律（普惠）**

- 宿主约束 / Intent / Assembler：**零专名、零单位、零项目白名单**。  
- 禁止「匹配到某标题就隔离某底稿」类实现。  
- 模型取舍失败 → 用 Trace + 评测改进提示与分层，**不**加宿主语义闸。

## 3. 与父规格权重矩阵的关系（不推翻，只澄清）

父规格 §5 仍然适用，口径改为：

| 原文易误解为 | 本补丁澄清 |
|--------------|------------|
| 「选层」= 宿主删掉某层 | **抬权 / 降权 / 形态变化**（如 lead 时 L3 用 toc **代替全文**——这是结构形态，对所有文稿一视同仁） |
| body「钉住 > 底稿」= 有钉住就丢掉底稿 | **标签与提示上钉住优先**；底稿仍可进包（或进「次优先」区），**是否采用由模型判** |
| 自对齐 | 明确要求模型可写：本轮采用哪些层、忽略哪些层（短句，不写长思考墙） |

**允许的宿主「结构形态」变化（普惠，非语义）：**

- `lead`：L3 结论底稿 → **目录摘要**（防标题底稿抢戏）——父规格已有  
- `chat`：不附结论底稿全文——父规格已有  
- 预算不够：按 §6.2 顺序砍——父规格已有  

**不允许的宿主「语义删除」：**

- 因「用户提到 X、底稿是 Y」而丢弃底稿  
- 因「压缩/精简」关键词而开关证据闸  
- 因公司名/场馆名写死隔离逻辑

## 4. baseDraft 生命周期（普惠状态机）

串味的主因往往是状态，不是模型智商。

```
[无底稿]
    │
    │ 用户「选定 / 光标 / 整篇」采用某卡
    ▼
[活跃 baseDraft = 该卡]
    │
    │ 用户清空对话 / 换工程
    ▼
[无底稿]

出多份 options ──✗──→ 不得自动 markBaseDraft
```

| 规则 | 说明 |
|------|------|
| **默认** | 新出多份 **不**自动设为 baseDraft |
| **设为底稿** | 仅用户显式采用卡片（选定/光标/整篇）或显式「作底稿」 |
| **进包** | 若存在活跃 baseDraft，以 L3 标签注入；模型可忽略 |
| **清空** | 清空对话一并清 baseDraft（父规格已有） |

这样换节时：若用户未采用上一节卡片，L3 不会自动塞满上一节全文；若已采用，模型仍应用取舍权决定要不要用。

## 5. 进包清单（每轮）

宿主**尽量给齐**（受预算约束），每块带层标签：

| 块 | 层 | 说明 |
|----|----|------|
| 本轮用户原文 | — | 不裁 |
| 【本轮焦点说明】 | 焦点 | Intent + 一句「取舍由模型」 |
| Task Card / rawPins | L1 | |
| 钉住范围 | L3-pin | 有则必给 |
| 结论底稿 | L3-draft | 有活跃 baseDraft 才给；lead 时 toc |
| 修剪 history | L2 | 助手多份只留短摘要（省 token） |
| 目录/精读 | L4 | 工具环；不整夹预塞 |

通识提示（示例，可微调，**禁止加专名**）：

> 下列分层仅供参考。请根据本轮用户意图自行决定采用哪些、忽略哪些；与本轮无关的历史结论或他段正文不要迁入本稿。

## 6. Intent 规则的定位（避免再吵）

| Intent 做什么 | Intent 不做什么 |
|---------------|-----------------|
| 给 Assembler 一个**可测的打包策略** | 不判决「这段业务该不该写某项目」 |
| 低置信时澄清 A/B | 不按业务词屏蔽材料 |
| 驱动状态条「本轮理解」 | 不替代模型思考 |

若未来 Intent 也交给模型：可作 **M2+**（一次 JSON 意图，失败回退规则）。**默认商用路径仍是宿主规则 Intent + 模型内容取舍**——两者分工，不是二选一打倒对方。

---

## 7. 与聪明程度 / 工具环

- **据实**：无精读不编数——证据层纪律，不是焦点专名规则。  
- **读哪些材料**：模型 tool 选型（工具环已定）；宿主不预塞整夹。  
- **写好**：质量闸 / 增强思考——不管「写哪一节」。
