> 相关：`2026-08-11-WPS本地素材与模板.md`、`2026-08-11-商业化总方案.md`、旧扩展 `materialTools` / `chatToolLoop`

---

## 1. 归类

用户要的是：在 WPS 里写公文时，右侧 AI **像 Cursor 一样能按需读本机工程材料**，数字随素材更新而准，而不是靠提示词假装「去看工作区」，也不是每次手工塞全文的捷径。

---

## 2. 对标

| 产品 | 学什么 |
|------|--------|
| **Cursor Chat/Agent** | 索引/目录帮助选型 → 工具精读 → 多轮回灌；侧栏可见「读了啥」 |
| **本产品 VS Code 扩展** | 工程根沙箱、三工具白名单、≤6 轮、中转不碰盘、`read_set` |
| **WPS 文件习惯** | 素材分区旁「刷新」；打开/改绑自动；发送前增量——少打扰 |

差异（公文 / WPS）：主材料为 **doc/docx**；主区始终是当前稿；读盘尽量不抢焦点、不长期留下素材标签页。

---

## 3. 铁律

1. **正文与素材不上云网盘**；中转只接收当轮必要片段。  
2. **读盘仅限已绑定工程根**（禁 `..`、禁任意盘符漫游）。  
3. **索引不能当写数依据**；凡据实写数 / 充填，必须对点名文件 **当场精读**。  
4. **无可用精读材料时**：说明缺什么，**禁止编造数字、单位与结论**。  
5. C 端只暴露「标准 / 增强」，不暴露厂商模型名。

---

## 4. 两层数据：索引 vs 精读

| 层 | 何时更新 | 内容 | 可否写数 |
|----|----------|------|----------|
| **索引** | 打开工程 / 改绑 / 用户点刷新 / **发送前增量** | 路径、标题、size、mtime、短摘要（约 300～800 字） | **否** |
| **精读** | 工具 `read_file` 或显式 `@` 引用当轮读取 | 文件现抽正文（有上限） | **是（唯一）** |

索引落盘路径（本机）：

```text
<工程根>/.gongwen/materials-index.json
```

建议字段（示意）：

```json
{
  "version": 1,
  "root": "D:\\...\\某工程",
  "updatedAt": "ISO-8601",
  "files": [
    {
      "rel": "素材/航博城进展.docx",
      "title": "航博城进展",
      "ext": ".docx",
      "size": 12345,
      "mtime": 1710000000,
      "summary": "……",
      "summaryChars": 400,
      "ok": true,
      "error": ""
    }
  ]
}
```

**模板**：进入同一刷新流程，但索引侧以 **标题 + 结构向短摘要** 为主（不承担写数）；精读模板仅在模型明确点名或用户引用时发生。

## 5. 刷新策略（更新到位 + 防忘点）

### 5.1 入口

| 触发 | 行为 |
|------|------|
| 打开助手且已有工程根 / 改绑成功 | 自动增量或首建索引（可底栏一句「已更新素材索引」） |
| 素材分区旁 **刷新** | **全量重扫**该夹（用户刚拷文件、不放心时） |
| **每次发送**撰写/精修 AI 请求前 | **按 mtime/size 增量**：有变则重抽该文件摘要并写回索引，再进入工具环 |
| 索引过期小点（可选） | 分区标题旁提示「有更新」；刷新或发送前同步后清除 |

### 5.2 精读新鲜度（数据常变场景）

- `read_file` / 引用读盘：**每次从磁盘现抽**，不复用会话内缓存的全文。  
- 若实现短 TTL 内存缓存：必须以 **mtime+size** 校验，对不上立即作废重读。  
- 索引摘要与精读冲突时：**以精读为准**；摘要只影响「选哪篇」。  
- UI「已读」条建议带时间：`已读《xx》· HH:mm`。

### 5.3 不做

- 不弹窗强迫确认刷新。  
- 不后台无限轮询全盘。  
- 不把整夹全文预塞进每一次请求。

## 6. 工具环（实打实，非捷径）

### 6.1 范围（本期 **A2**）

- **撰写**对话（立意 / 搭架 / 充填 / 自由问）走工具环。  
- **精修**出方案同样可带 `workspace` 索引摘要 + 工具精读（与撰写共用已读状态机更佳；至少共用索引与 `read_file`）。  
- 会话级持久化 `read_set`（仅路径列表）可做；**全文不落会话库**。

### 6.2 职责

```text
WPS 侧栏
  · 工程根 / 索引文件
  · 执行 list_files · read_file · search_materials
  · 多轮工具环 · 已读 UI
        │  HTTPS：短票 + 选区/上下文 + tool_results + read_set + workspace
        ▼
云中转
  · 验票 · 额度 · 调模
  · 不执行路径、不存素材全文
```

### 6.3 工具白名单

| 工具 | 作用 | 限额（量级对齐现网） |
|------|------|----------------------|
| `list_files` | 列工程约定目录（优先吃索引，必要时回落扫盘） | 每夹约 40 条 |
| `read_file` | 读 md/txt/**doc/docx** 正文 | 单次默认约 12k 字（上限约 40k） |
| `search_materials` | 在索引摘要 + 可读正文中检索 | 约 5 命中 × 800 字 |

沙箱：相对工程根；拒绝越界；**无写盘工具**。

### 6.4 环路

1. 发送前：增量刷新索引。  
2. 请求携带：选区/`context_md`、`workspace`（目录+摘要，控体积）、`read_set`、可选 `@` 预读正文、`tool_results`。  
3. 中转返回 `tool_calls` → 本机执行 → 更新已读 UI → 再请求。  
4. 最多 **6** 轮；`round≥4` 可 `force_final`；同一路径重复 `read_file` 则强制收尾。  
5. 最终 `reply`（及可选 `edit`）；无合格精读且属据实意图 → 阻断瞎编数字。

首轮即带索引摘要，目标是常见路径 **约 2～3 次模型往返**（选型 → 精读 → 成文），避免无目录时空转。

### 6.5 中转协议

复用现网 `/api/chat` 已支持字段：`tool_results`、`read_set`、`force_final`、`workspace`、`allow_edit` 等。  
中转不读盘；缺原生 function calling 时用与扩展相同的 JSON tool 协议兜底。

## 7. UI（右侧 + 工程栏）

### 7.1 工程栏 · 素材

- 分区标题旁：**刷新**（全量）。  
- 可选：过期小点。  
- 底栏/状态：索引中 / 已更新 N 个文件 / 失败原因。

### 7.2 对话区（对标 Cursor 上下文可见性）

- 进行中步骤：`正在同步素材索引…` / `正在读《xx.docx》…` / `正在作答`。  
- 常驻 **已读 N**：短文件名（可展路径）+ 可选时刻。  
- `@` 引用条保留（Cursor `@file` 语义），**不能替代**工具环。  
- 无材料据实失败时：人话提示「请将材料放入素材/ 或点刷新后再试」。

## 9. 验收

- [ ] 未手动 `@` 时，充填仍会经索引选型并 `read_file` 精读后再答。  
- [ ] 修改素材文件并保存后，**不点刷新**直接发送，精读内容为新数据（发送前增量 + 现抽）。  
- [ ] 点刷新后列表与索引与磁盘一致（含新拷入文件）。  
- [ ] 侧栏可见「已读哪些」（及可选时间）。  
- [ ] 读素材不长期抢走当前稿标签。  
- [ ] 越界路径拒绝。  
- [ ] 无合格材料时不编数字。  
- [ ] 未登录 / 额度用尽行为与现网一致。

## 11. 确认记录

| 项 | 结论 |
|----|------|
| 形态 | Cursor 式工具环 + 本地索引，拒捷径整夹预塞 |
| 范围 | **A2**：撰写 + 精修共用材料能力 |
| 刷新 | 手动全量 + 打开/改绑自动 + **发送前增量** |
| 新鲜度 | 索引辅助选型；**精读每次现抽**；摘要不得写数 |
| 模板 | 进刷新/索引，偏结构摘要；写数仍以素材精读为准 |
