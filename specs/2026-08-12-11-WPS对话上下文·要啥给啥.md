## 0. 定调

**宿主不做语义判断。**  
第一包：**本轮要求 + 钉住原文（有则附）+ 其余有什么的短清单**。  
近轮对话：**走 messages**。用户原话 + 助手口语；**同一钉住才带最近一次卡片全文；换钉不带卡片**（见 06）。  
全文 / 素材：模型点名再给。钉住是用户划的工作面，不是宿主猜该写哪。  
第一包【还有什么】**不列** base_draft，也不把已落稿 md 再塞进对话。

宿主只保留协议：出结论/给多份的 JSON、点选层级对应的井号（落稿套字体）。

## 1. 首包必给

| 块 | 内容 |
|----|------|
| 用户本轮原文 | 不裁 |
| **近轮对话** | messages：用户原话 + 助手口语；**同钉住才带最近一次卡片；换钉不带**（见 06） |
| **钉住原文（有则附）** | 用户划的工作面；用不用由模型判断 |
| JSON / 井号 | 出结论、给多份、点选层级 → 只放 system |
| **【还有什么】** | 全文/素材：有无 + 字数；**正文不预塞**；不列底稿、不列近轮对话 |

清单项（普惠，无专名）：

- `pin` 钉住范围（第一包已附原文；也可再 fetch）  
- `doc_full` **当前完整正文**（字数）  
- 素材：`list_files` / `search_materials` / `read_file`

---

## 2. 点名工具

| 工具 | 作用 |
|------|------|
| `fetch_context` | `keys`: `pin` \| `doc_full`（可多项）。**不要** `history` / `base_draft`（对话走 messages；稿信正文） |
| `list_files` / `search_materials` / `read_file` | 素材 |

模型要 `doc_full` → 给当前完整正文。宿主不改写成摘要顶替。  
仅存在传输硬顶（API 体积）时原样截断并标明 `truncated`+总字数——**不是内容裁判**。

## 3. 禁止（宿主）

- 按专名/关键词决定给不给  
- 猜 intent、写【本轮焦点说明】、逼 reply 首句对齐 intent  
- 「请在钉住范围内撰写」「钉住优先于底稿」「无关勿迁入」  
- A/B 澄清打断（统领全文 vs 打磨标题）  
- 正则抽取任务卡当「既定要点」压过本轮  
- 写前对齐卡进模型包  
- 首包预塞钉住 / 底稿 / 全文 / 任务卡  
- 出多份自动 `baseDraft`（仍仅选定/光标/整篇；已落稿 md 不进下一轮；未落稿最近一轮卡片要带，见 06）
