## 0. 为什么要单开这条线（又必须和上下文一起研究）

此前大量工作解决的是**送什么进模型**；本方案解决**怎样对齐与挑稿才像笔杆子**。两边不是两套产品：

| 层 | 更偏上下文 | 更偏聪明程度 | 共享 |
|----|------------|--------------|------|
| 发送前 | Intent / 分层 / 预算 | 要不要澄清、多份是否服务立意 | **本轮对齐思考**（短理解） |
| 发送中 | 读哪些材料、焦点块 | 证据是否够写好 | 工具环精读 |
| 发送后 | Trace：选错层？ | Critic：稿弱在哪一维？ | 状态条 / GwLog |
| 评测 | U1–U9 焦点用例 | 金标 / 退稿 / 盲测 | 同一批任务可双记分 |

单位里常说某人是「材料高手」「大笔杆子」——**不全是「文笔华丽」**，更是：会立意、会取舍、会借材料、会压口气、会躲雷、会一次过关。人和人写的不一样；**怎样系统性地逼近甚至超过本单位最好的笔杆子**，才是「聪明程度」课题。

商业化总方案已埋下同一句：**本地旧稿学口气 + 素材据实 + 交稿前核对**。本文件把它升格为可研究、可评测、可分期的产品线。

### 0.1 和 DeepSeek「思考过程」的关系（联合研究的关键切口）

用户直觉对：**学「先想清楚再写」就是在提高聪明程度**——大笔杆子落笔前也会在脑子里过：场合、材料、忌口、结构。DeepSeek 类产品把这类过程外显成很长的思维链。

| 借什么（聪明） | 不借什么（形式/体验） |
|----------------|------------------------|
| **对齐再写**：本轮到底写冒段还是改标题、依据够不够、口气跟谁 | 把完整 CoT 刷进对话区当「智商表演」 |
| **可检核的中间结论**：意图、依据条数、参照、待核实（可进状态条 / Trace） | 默认双轮「先分析会再出稿」税（与上下文终局冲突） |
| **增强档可选**：模型原生 thinking / 轻量 Critic，用于难稿、交稿前 | C 端展示厂商名；用思考长度当质量 KPI |

因此：

1. **宿主已做的「本轮理解」状态条** = 对齐思考的**可见层**（上下文 M1），同时是聪明程度的**过程入口**。  
2. **下一步可联合研究的**：对齐思考是否升级为结构化「写前卡片」（仍短）：`意图 | 依据 | 参照 | 风险`——既服务焦点，也服务质量闸。  
3. **模型侧 thinking**（若中转/增强档支持）：默认**只用于提高成稿**，摘要进 tip / `quality.trace`；全文思考仅调试或用户显式展开。

**口号修正：** 不是「不要思考」；是「**思考要对齐成稿，展示要对齐办公习惯**」。

## 0.2 形式 vs 质量（仍要分清，避免混测）

| 已在做的 | 解决什么 | 单独不够时 |
|----------|----------|------------|
| 上下文 Kernel / 意图 / 分层 | 写偏、抢戏、丢任务 | 焦点对了句子仍干巴 → 要风格/Critic |
| 工具环 / 精读 | 能读到、能据实 | 读到了仍不会取舍 → 要立意/多份 |
| 层级落稿 / 安全写回 | 落得进、版式对 | 与文采无关 |
| 状态条「本轮理解」 | 对齐过程可见 | 可演进为质量短摘要（§0.1） |
## 1. 北极星

**对老手的承诺（质量版）：**  
不是「会生成一段公文腔」，而是：**在同等材料与任务下，成稿更少被退、更少被改结构、更少被挑口径；在熟悉本单位参照后，口气与判断接近本单位大笔杆子，并在「据实与覆盖面」上可超过单人记忆力。**

| 商用说法 | 工程含义 |
|----------|----------|
| 比肩大笔杆子 | 盲测中，评审难稳定分出「人写 / 机写」；退稿点不高于该单位优秀稿均值 |
| 某些维度超过 | **检索覆盖、数字核对、旧稿撞车、易错口径**——机器可系统胜出 |
| 不假装万能 | 无材料不编数；无参照不强装「本单位味」；判断不确定处显式标出 |

**非目标（明确不做）**

- 用一套全国通用「公文美文库」冒充各单位笔杆子  
- 硬编码某单位/某项目/某领导讲话金句（普惠铁律）  
- 堆超长 CoT 当聪明；用户要的是**好稿**，不是思考墙  
- 用本地空壳模板顶替模型结论（与上下文方案一致）

## 3. 大笔杆子到底「聪明」在哪（能力分解）

人和人写得不一样，差异可拆成六维。产品要分别养、分别测，禁止用「文笔」一个词糊弄。

```
                    ┌─ 立意与取舍（写什么、不写什么）
                    ├─ 结构与节奏（层次、对仗、冒段收束）
  大笔杆子 ─────────┼─ 口气与身份（像本单位、像此文种、像此场合）
                    ├─ 据实与证据链（数从哪来、事能否落）
                    ├─ 口径与避雷（敏感表述、前后一致）
                    └─ 改稿判断（哪里动刀、一改到位）
```

| 维度 | 人怎么赢 | 机器可赢在哪 | 机器易翻车 |
|------|----------|--------------|------------|
| **立意取舍** | 懂领导要什么、场合忌什么 | 任务卡 + 澄清 + 多份对比供人选 | 材料全灌导致面面俱到、没有锋芒 |
| **结构节奏** | 多年标题手感 | 层级约束 + 参照稿结构指纹 + 对仗检查 | 空壳「一是二是」、假对仗 |
| **口气身份** | 泡在本单位稿子里 | **本机参照稿 / 往年稿风格指纹**（商业化已写） | 全国网文公文腔、串味 |
| **据实证据** | 翻材料快、记得住 | **索引选型 + 精读 + 禁止无依据写数**（工具环已立） | 索引当依据、幻觉数字 |
| **口径避雷** | 知道本单位红线 | 本机词库/易错表 + 交稿检查单 | 通用敏感词误伤；漏单位专属口径 |
| **改稿判断** | 知道「只动这一句」 | 精修钉住 + 意图焦点（上下文 Kernel） | 整段重写毁掉已定稿 |

**关键洞察：**  
「比大笔杆子还好」**不是每一维都碾压人**，而是：

1. **人强维（立意、场合判断）**：产品用澄清、多份、人机共选，不装比领导更懂政治。  
2. **机强维（覆盖、核对、对照、不疲劳）**：系统化超过单人。  
3. **可学维（口气、结构习惯）**：只从**本机参照**学，越用越像本单位——这是差异化护城河。

## 4. 「人和人写的不一样」→ 产品怎么处理

| 现象 | 错误做法 | 正确做法 |
|------|----------|----------|
| 甲乙笔杆子风格不同 | 强行统一成「标准公文腔」 | **参照稿可选、可换**；风格跟参照走，不跟产品默认腔走 |
| 同一人讲话稿 vs 请示不同 | 一套提示打天下 | **文种/场合标签**（用户选或任务卡推断）+ 不同检查单 |
| 新手要「像笔杆子」、老手要「听我的」 | 只服务一种 | 模式：**仿参照** / **听本轮指令优先**（默认后者压过空套话） |
| 好稿难定义 | 凭感觉调提示词 | **金标集 + 退稿点标注**（见 §7） |

风格资产（只在本机）：

| 资产 | 来源 | 用途 | 禁区 |
|------|------|------|------|
| 参照稿 | 用户点选往年总结/汇报等 | 口气、标题习惯、收尾套话、长短句 | 禁止整篇抄袭送出；只抽指纹与片段 |
| 工程旧章 | 同工程历史章节 | 防重复、防撞车 | 不上云库 |
| 易错/口径表 | 用户改过的词、单位惯用 | 避雷与统一 | 默认本机；可选是否进当轮提示 |
| 精读素材 | 工具环 read | 据实 | 索引不得写数 |

## 5. 聪明程度的三条技术路线（利弊）

### 路线 A · 加厚提示与手册（轻）

下发文种手册、对仗示例、禁编造纪律；宿主拼焦点与材料。

- **利**：快、成本低、易运营上下架  
- **弊**：上限明显；换单位不增「本单位味」；难证明比笔杆子好  
- **定位**：基线，必须有；**单独不够**

### 路线 B · 证据与风格双引擎（主推荐）

```
本轮意图（Context Kernel）
    + 精读证据包（ToolLoop，可引用片段）
    + 风格指纹（参照稿结构化摘要，非全文）
    → 一稿生成
    → 交稿前质量闸（据实/对仗/撞车/口气偏离）
    → 不达标则定点重写或标「待核实」，禁止糊弄过关
```

- **利**：对齐商业化真优势；可测；机强维可超过人  
- **弊**：要工程化风格指纹与评测；闸太严会烦、太松无意义  
- **定位**：**聪明程度主路径**

### 路线 C · 对齐思考 / 可选深检（与上下文联合，慎用税）

大笔杆子的「腹稿」≈ DeepSeek 的思考：**先对齐再落笔**。产品分三档，避免和「一轮出稿」打架：

| 档 | 做什么 | 何时 |
|----|--------|------|
| **C0 宿主对齐（默认）** | Intent + 分层 + 状态条短理解；必要时一句澄清 | 每轮；税≈0 |
| **C1 结构化写前卡（联合研究）** | 模型或宿主产出短 JSON：`intent/evidence/style/risks`，再写稿；UI 只露摘要 | R1–R2 试验；失败则跳过直接写 |
| **C2 增强深检** | 原生 thinking 摘要进 Trace，或 Critic 第二趟只挑刺不重写全文 | 增强档 / 交稿前；用户可关 |

- **利**：把「学 DeepSeek」落到**提高成稿**，而不是换皮聊天  
- **弊**：C1/C2 有延迟与费用；中间卡若太吵会烦  
- **纪律**：默认路径仍是 **C0 + 一路出稿**；禁止把 C2 思考全文倾倒进气泡

**推荐组合：** **A 地板 + B 主线 + C0 常开 + C1/C2 可研可开。**  
上下文里程碑（M1…）与聪明程度（R0…）**共用同一批评测任务**：一题双记分（焦点分 / 质量分）。

## 6. 终局能力地图（质量内核 Quality Kernel）

与 Context Kernel / ToolLoop **并列**，不互相吞掉：

```
┌─ UI：质量提示（短）/ 已读材料 / 参照稿芯片 / 交稿检查结果 ─┐
├─ Context Kernel：意图、任务卡、焦点、历史预算 ────────────┤
├─ ToolLoop：选型 → 精读 → 证据片段 ──────────────────────┤
├─ Quality Kernel（本方案）───────────────────────────────┤
│  StyleFingerprint · EvidenceBinder · DraftCritic       │
│  · UnitLexicon · AcceptanceChecklist                   │
├─ Relay / 模型：只消费打包好的「写什么 + 依据 + 风格约束」──┤
└─ 评测台（研发）：金标集、盲测、退稿点统计 ────────────────┘
```

| 模块 | 职责 | 输入 | 输出 |
|------|------|------|------|
| **StyleFingerprint** | 从参照稿抽「像谁」 | 用户选中的本机 md/docx 片段 | 结构习惯、称谓、句长、标题句式、禁用抄袭全文 |
| **EvidenceBinder** | 稿中断言 ↔ 精读片段 | edit.md + read_set 摘录 | 带依据标注或「待核实」强制位 |
| **DraftCritic** | 交稿前挑刺（可同模型 JSON、禁重写全文） | 候选稿 + 检查单 | 问题列表；可选定点改写建议 |
| **UnitLexicon** | 本机口径/易错 | 用户维护或从采纳稿学习 | 替换建议 / 警告 |
| **AcceptanceChecklist** | 文种交稿单 | 文种 + 任务卡 | 人可读勾选项；未过可拦「导出自信」不拦编辑 |

原则：

1. **质量闸默认轻量**（标问题 > 强行改稿）；用户授权后再改。  
2. **风格只跟参照，不跟产品臆造单位。**  
3. **Critic 不得替代写手乱改已定标题**（服从本轮意图）。  
4. 与状态条配合：可显示「已仿参照《××》· 依据 3 处 · 待核实 1」——仍是短句，不是长思考。

## 7. 如何证明「更聪明」（评测才是课题的一半）

没有评测的「调提示词」不算研究聪明程度。

### 7.1 金标与样本

| 集 | 内容 | 用途 |
|----|------|------|
| **金标人稿** |  anonymized：任务说明 + 可用材料包 + 大笔杆子定稿（用户自愿提供本机样本，不上公网训练集除非另签） | 盲测对照 |
| **退稿集** | 真实被退理由标签：结构/口气/数字/口径/跑题… | 回归：新版本不得增加该类失败 |
| **对抗集** | 故意缺材料、故意多材料噪声、故意短指令「先完成这段」 | 测据实与焦点，不测文采 |

### 7.2 评分维度（建议 1–5，可人工 + 半自动）

| 分 | 含义（对评审） |
|----|----------------|
| 立意取舍 | 是否抓住场合重点，有无正确的「不写」 |
| 结构 | 层次是否清、标题是否站得住 |
| 口气 | 是否像指定参照（有参照时）；无参照则「得体公文」即可 |
| 据实 | 关键数字/事实能否指回材料；无中生有即不及格 |
| 可采用度 | 老手预估还要改几刀才能上会 |

**机器可自动的粗检（辅助，不替代人审）：** 无依据数字、标题井号/层级、与参照稿 n-gram 过高（抄袭风险）、与旧章重复率。

### 7.3 成功判据（分期）

| 阶段 | 判据 |
|------|------|
| R0 研究基线 | 固定 10 个任务：现网 vs 仅加手册，人工分出差距与失败类型分布 |
| R1 证据优先 | 对抗集上「无材料编数」→ 0；有材料关键数命中率可统计 |
| R2 风格像人 | 有参照时，盲测「更像参照」胜率 ≥ 非参照基线；抄袭相似度低于阈值 |
| R3 比肩笔杆子 | 金标任务上，综合分达到该金标稿的 ±0.5 分带，或退稿点 ≤ 金标 |
| R4 机强维超过 | 数字核对 / 撞车检出 / 材料覆盖 系统优于单人限时笔杆子（可单独测） |

## 9. 用户可见形态（质量，不堆面板）

对标 Cursor / 交稿检查，右栏保持从属文档：

1. **写作前（可选）**：选「参照稿」芯片（商业化已述）——未选则不强装本单位味。  
2. **写作中**：已读材料条 + 短理解状态条；需要时「本轮依据：文件名#段落」。  
3. **出结论后**：轻量质量条（待核实 / 可能撞车 / 偏离参照）——点开才看详情。  
4. **交稿前**：检查单；不通过可仍编辑，但明示风险。

禁止：默认弹出长篇「AI 思考过程」；禁止把质量做成第二个 IDE。

## 10. 研究与实现分期

| 期 | 目标 | 产出 | 依赖 |
|----|------|------|------|
| **R0** | 说清差距 | 本规格 + 10 题基线评测表 + 失败类型标签 | 现网即可 |
| **R1** | 据实变硬 | 证据绑定字段（稿内或旁注）；无依据强制待核实；对抗集回归 | 工具环精读稳定 |
| **R2** | 像本单位 | 参照稿指纹 v1；仿写约束进包；盲测「像参照」 | 本机选参照 UX |
| **R3** | 交稿闸 | DraftCritic + 文种检查单；增强档可选深检 | R1/R2 |
| **R4** | 机强维产品化 | 旧稿撞车、数字台账、口径表学习 | 工程面板/旧章 |

每期结束：**先看评测表，再决定要不要改提示或加模块。** 禁止「感觉写好了」就推版本。

## 11. 风险与伦理

| 风险 | 对策 |
|------|------|
| 学参照学成抄袭 | 指纹用抽象特征 + 相似度上限；金句级复用需用户明示 |
| 假装超过笔杆子导致信任崩塌 | 对外话术用「少退稿、据实、像本单位」；对内用盲测数字 |
| 单位政治判断误伤 | 立意维以人为主；机只提供多份与风险标 |
| 隐私 | 金标与参照默认本机；不上云文稿库（商业化铁律） |
| 普惠 | 零硬编码单位专名；专名只来自用户与精读 |

## 12. 开放研究题（允许后续迭代改结论）

1. 风格指纹最小字段集是什么（句长、标题模板、称谓、段首习惯…）？  
2. Critic 用同模型 JSON 是否够稳，还是要增强档另一模型？  
3. 「比笔杆子好」的对外话术如何既敢说又不翻车？  
4. 多份方案（给多份）是否应变成质量研究的一等公民（分歧 = 立意维的人机接口）？  
5. 讲话稿 / 请示 / 总结是否分三条检查单，还是任务卡动态生成？  
6. **联合：** C1「写前短卡」用宿主规则拼，还是让模型先吐 JSON？与 DeepSeek 原生 thinking 谁涨质量分更划算？  
7. **联合：** 状态条从「理解：冒段」演进到「理解：冒段 · 依据2 · 仿参照」的信息密度上限在哪（仍一眼可读）？

## 15. 一句话收束

**大笔杆子的聪明 = 六维能力；落笔前的腹稿 = 对齐思考（DeepSeek 该学的那一层）。**  
上下文与聪明程度一起研究：送对材料、想清焦点、短可见对齐（思考摘要可进状态条），再用参照与证据把稿写过关——**思考服务成稿，展示服务办公**，而不是长思考墙或空形式。
