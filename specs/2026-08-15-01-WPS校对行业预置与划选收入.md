## 一句话

点「开始校对」就能用。行业词我们写好。用户自己的词和数，划选收入，跟账号走。

## 已定

| 项 | 定法 |
|--|--|
| 主路径 | 校对条：选区\|全文 → 开始校对。设置不是前置 |
| 行业预置 | 政务易错/口径随产品带上，默认开；设置里可关整包或删条 |
| 收入入口 | **校对条「收入」**，对**当前正文选区** |
| 收入三种 | 别再报这些（白名单）· 这种错必须改（易错对）· 收到数字表 |
| 数字表 | 模型从选区抽出条目，人点确认再入库；无表时核验不跑 |
| 结果条 | 可快捷：不是错→白名单；必须改→易错（与「收入」同一仓库） |
| 设置 | 只查看/删除已收的；不当录入台 |
| **用户独立 · 云端** | 「我的」词/数是**账号资产**，登录短票读写，换电脑跟账号。行业预置另仓（产品包），两仓不合并。正文/素材仍不上云 |
| **库形态** | **推荐**：中转现有 `control.sqlite` 加表，按 `user_id` 隔离（同 `user_templates`）。不是每人一台物理库。API 一律 `WHERE user_id=?`；管理员看不见用户词库 |
| **登录** | 收入 / 拉「我的」必须已登录。未登录：提示先登录，不写本机当主库 |
| **校对读表** | 中转凭短票读该用户云表 + 行业预置，再判。客户端不必每次 POST 整表 |
| 判错 | **全部由模型判**。用户白名单/必改/数字表只当证据写入提示；无数字表则数据核验不跑。宿主不再跑标点/格式/夹数字等本地规则 |
| 换钉 | 与校对结果清法仍按现网：切 Tab / 再点校对清上一轮结果 |
