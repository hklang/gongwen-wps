# WPS 工作选区：可反复换选（设计方案）

> 日期：2026-08-11  
> 依据：`Word/Code/想构思.md`（先对标再发明；确认后再写代码）  
> 范围：`Word/wps-spike` 独立窗侧栏 · 精修/撰写工作选区  
> 现状痛点：**选中一次之后不能再选中**

---

## 1. 归类

本质不是「缺一个按钮」，而是：

> **工作选区（AI 上下文）的状态机坏了**——第一次钉住之后，用户无法稳定地「换一块再钉」。

用户要的产品行为：

1. 正文划选 A → 侧栏确认已选定  
2. 再划选 B → **立刻**变成新选定（可反复）  
3. 需要时勾「扩选同级标题」把同级标题并入工作选区  
4. **不改正文格式**（不涂黄）  
5. 全文气泡默认收起，用户主动展开  

---

## 2. 对标

| 产品 | 学什么 |
|------|--------|
| **本产品 editor 精修** | 选定以**主区划选为准**；侧栏芯片只是状态条（只读摘要）；**随时可换选**；点空白取消。已废弃「重选冻结」。 |
| **Cursor 附件 / 飞书智能伙伴** | 上下文可换；换选 = 新划选覆盖旧附件，不必先「解锁」。 |
| **Word 审阅窗格** | 主区选区是真相；侧栏跟随。独立窗场景要额外处理焦点。 |

**禁止**：把「点侧栏芯片」当成唯一选中入口，又在已有 `work` 时把点击改成「展开气泡」——这会锁死换选。

---

## 3. 根因（当前实现）

代码：`wps-spike/js/taskpane.js` → `#aiSel` 点击逻辑。

```text
已有 work 时：
  multi || sameAnchor || live 为空  → 只「展开」气泡，不重新 pin
否则才 pinWorkFromDoc
```

叠加 **WPS 独立窗焦点** 特性：

1. 用户在正文划好 B 后，**鼠标点到侧栏**时，焦点先离开文档。  
2. 点击回调里再读 `Selection`，常常已经是 **空 / 折叠 / 仍停在旧锚点**。  
3. 于是命中 `!live` 或 `sameAnchor` → **只展开、不换选**。  
4. 扩选同级后 `items.length > 1`，`multi === true` → **后续点击永远只展开**。

结论：  
**「用点击芯片的那一刻去读 Selection」不可靠**；再叠加「有 work 就优先展开」→ 表现为「选中一次就不能再选」。

---

## 4. 目标状态机

```text
                    ┌──────────────┐
         清除/取消   │   未选定     │
         ◄──────────│  work=null   │
         │          └──────┬───────┘
         │                 │ 捕获成功（见 §5）
         │                 ▼
         │          ┌──────────────┐
         │          │   已选定     │◄──── 再次捕获成功（覆盖）
         └──────────│  work= {...} │
                    └──────┬───────┘
                           │ 用户点「展开」
                           ▼
                    ┌──────────────┐
                    │ 气泡展开     │  （仅 UI，不改 work）
                    │ 再点/Esc 收起│
                    └──────────────┘
```

原则：

- **捕获**与**展开**必须是两条入口，不能挤在同一个「整颗芯片单击」上且互相抢。  
- **后一次捕获永远覆盖前一次**（与 editor「随时改选」一致）。  
- 取消选定：显式「清除」或等价手势（见下）；不要靠「点芯片」隐式取消。

---

## 5. 推荐方案（确认后实现）

### 5.1 捕获时机：焦点离开文档前先记一笔（主路径）

对标：editor 在主区 `mouseup` 落选；WPS 独立窗没有同源 DOM，改用：

| 手段 | 作用 |
|------|------|
| **A. 文档侧松手即预捕获** | 在 `Application` 可挂的选区变化 / 定时轻量轮询（仅对话框可见时，≤5Hz）里，把当前 `Selection` 写入 `state.live`（影子选区：text/start/end/heading）。**不写入 work，不改正文。** |
| **B. 显式「采用选区」** | 芯片右侧固定文案 **「选中」**（有 work 时仍显示「选中」表示可换选）；点击 = `work = live || 此刻 Selection`。**永不**因「已有 work」改去展开。 |
| **C. 展开另入口** | 截断时显示 **「展开」** 为**独立小按钮**（或芯片二次点击仅当 `live` 空且用户点在摘要区）。与「选中」拆开。 |

推荐落地组合：**A + B + C**。

- 用户划选 B → `live` 已更新（侧栏可淡提示「待采用 · N 字」）。  
- 点「选中」→ `work = live`，芯片变「已选定」。  
- 再划选 C → `live` 变；再点「选中」→ 覆盖。  
- 点「展开」→ 只看 `work` 全文。

即便 B 点击时 Selection 已空，只要 **A 在失焦前写入了 live**，仍能换选。这是独立窗场景的关键。

### 5.2 「扩选同级标题」

- 勾选 = 偏好：下次「选中」时，若锚点在标题上，则 `work = selectSiblingHeadings()` 的标题行文本。  
- 或：已有单标题 `work` 时勾选 → 立即按当前锚点扩成同级并入 `work`（仍不涂色）。  
- 取消勾选：**不自动改 work**；下次「选中」按普通划选。  
- 多标题 `work` **不得**封锁再次「选中」。

### 5.3 清除

侧栏在已选定时提供轻量 **「清除」**（或芯片 `×`）：

- `work = null`，`live` 可保留  
- 与 editor「点空白取消」对齐；WPS 主区点空白难监听时，用显式清除兜底  

### 5.4 不做

- 正文涂黄 / Highlight（已否决）  
- 恢复「选当前段 / 扫同级」按钮条  
- 有 work 时把整颗芯片单击改成「展开」  
- 依赖「点击瞬间 Selection 一定还在」

## 6. 落地清单（确认后改这些）

| 项 | 文件 | 做什么 |
|----|------|--------|
| 状态 | `js/taskpane.js` | 拆 `state.live` / `state.work`；芯片文案区分「待采用」与「已选定」 |
| 点击 | `js/taskpane.js` | 「选中」永远 `pin from live\|Selection`；「展开/收起」独立，不与选中抢 |
| 预捕获 | `js/taskpane.js` + 必要时 `js/docapi.js` | 对话框打开期间轮询或事件刷新 `live`（可配置间隔，失焦前最后一次为准） |
| 清除 | `ui/taskpane.html` | 已选定时显示清除 |
| 扩选 | 现有 checkbox | 只影响 pin 策略，不锁死换选 |
| 规格 | 本文 + `2026-08-11-WPS基础功能MVP.md` 交叉引用 | 实现后把 MVP 里过时的点击逻辑删掉 |

### 建议函数（名称可微调）

- `readLiveFromDoc()` → 更新 `state.live`  
- `commitLiveToWork()` → 「选中」；支持 expandSib  
- `clearWork()` → 清除  
- `toggleSelPop()` → 仅气泡  
- `startLiveWatch()` / `stopLiveWatch()` → 窗体 show/close

## 7. 验收（必须可反复）

1. 划选 A → 点选中 → 芯片显示 A；不弹气泡；正文无涂色。  
2. 再划选 B → 点选中 → 芯片变为 B（**不得**仍停在 A 或只弹气泡）。  
3. 勾选扩选同级（光标在「一、」）→ 点选中 → work 为同级标题行文本；再划一段正文 → 点选中 → 变为该正文。  
4. 已选定后点「展开」看全文 → 「收起」；再换选仍正常。  
5. 点「清除」→ 未选定；可再选。  
6. 连续换选 ≥5 次无卡死。  

---

## 8. 落地状态

已收束为：**划选 →「钉住」**（唯一主按钮）→ 落入右侧文字条；点文字条展开/收起；`×` 清除。  
后台保留 `live` 预捕获，保证可反复换钉。精修可选勾「扩选同级标题」。
