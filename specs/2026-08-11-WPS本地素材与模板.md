# WPS 加载项：本地素材夹 / 模板夹（设计方案）

> 2026-08-11 · 依据 `想构思.md`（先对标再发明；**确认后再写代码**）  
> 对标现网：VS Code 扩展工程里的 `素材/`、`模板/`、官方同步包  
> 已定商业铁律：正文/素材不上云网盘；云端只发手册/官方模板/「我的」短骨架

---

## 1. 归类

用户要的是：

> 在 **WPS 里写 docx** 时，仍能像以前一样用到本机 **素材文件夹、模板文件夹**（读材料据实写、套结构），而不是只靠对话框里粘贴。

这不是「再做一个资源管理器」，而是：**本机材料入口 + 注入 AI/插入正文** 的能力，宿主从 VS Code 换成 WPS。

---

## 2. 对标

| 产品 / 能力 | 学什么 |
|-------------|--------|
| **本产品 VS Code 扩展** | 工程根下约定目录 `素材/`、`模板/`；对话 `@` / 工具读文件；官方包同步到本机缓存 |
| **WPS「打开 / 另存 / 文件夹」** | `Application.FileDialog`（打开 / 选取文件 / 选取文件夹）——用户授权选路径，符合办公习惯 |
| **双轨模板规格** | 官方 / 我的走云 API；本机 `模板/` 只作缓存，不是「我的」权威源 |
| **尖刀规格已写边界** | 不要把 md 工程壳整锅搬进侧栏；素材改「选文件 / 云模板 / 注入片段」 |

---

## 3. 能力边界（必须先认清）

| | VS Code 扩展 | WPS JS 加载项 |
|--|--------------|---------------|
| 读盘 | Node `fs`，任意工程路径 | **无 Node**；侧栏是网页 + `Application` |
| 列目录 | 直接扫文件夹 | 需 **FolderPicker 选根**，再靠宿主 API / 组件读目录 |
| 读文本 | `fs.readFile` | 候选：`FileSystemObject` / 打开只读文档取正文 / **本地小中转**（与现 `gongwen-relay` 旁路或本机 agent） |
| 正文载体 | md | **当前打开的 docx**（主稿）；素材仍建议 md/txt/docx |

结论：

1. **可以做**本地素材/模板，但要以「用户点过的工程根」为界，不能默默扫全盘。  
2. **不能假设**和扩展里一样随便 `fs.readdir`。  
3. 读文件实现要 **单独做成适配层**，失败时降级为「选取文件 → 粘贴/导入」。

---

## 4. 推荐产品形态（简洁）

### 4.1 一个「公文工程根」

用户第一次（或设置里）点 **「绑定工程文件夹」** → `FileDialog(FolderPicker)`。  
约定子目录（与扩展对齐，降低双端心智）：

```text
<工程根>/
  素材/          ← 据实写作材料（md/txt/docx）
  模板/          ← 本机缓存（官方同步 + 选用落地）；权威「我的」仍在云
  （可选）版本/  ← 后置，WPS 侧可先不做
  当前稿.docx    ← 正在写的正文（或用户任意打开的 docx，根目录只作材料锚点）
```

路径记在本机（加载项 `localStorage` / 注册表 / 文档自定义属性三选一，优先 **localStorage + 工程根下 `.gongwen-wps.json`**）。

**不强制**当前 docx 必须躺在工程根里；只要求「读材料时以该根为准」。

### 4.2 侧栏入口（少按钮）

**主用户故事（你要的）：**  
用户把相关 **docx（及 md/txt）放进工程 `素材/`** → 撰写/精修时，系统在**后台读取**这些文件正文 → 片段送给模型据实写 → **不必**在 WPS 里把它们开成标签页。

精修/撰写下方薄条：

| 入口 | 行为 |
|------|------|
| **素材** | 列出 `素材/`；勾选/点选纳入本次上下文（默认可「自动带上夹内已索引文件」的标题+摘要，需要时再读全文） |
| **模板** | 云端官方 / 我的 + 本机缓存；插入选区 |
| **绑定工程** | 设置级 |

对标扩展：`@素材` / 工具 `read_file`——读进来用，不当第二个编辑器。


### 4.3 与「钉住」的关系

- **钉住** = 当前 docx 里的工作选区（改哪一段）  
- **素材** = 额外上下文（从哪写、数字依据）  
二者并列；出方案时 `work + 已选素材片段` 一并送中转。

## 5. 技术路径（分阶段）

### P0 — 能用即可（建议先做）

1. **绑定工程根**（FolderPicker）+ 持久化。  
2. **添加素材**：FilePicker 多选 → 把**路径列表**记入工程索引（`.gongwen-wps.json` 的 `materials[]`）；能读文本则预读摘要，不能读则仅路径+用户粘贴。  
3. **读文本适配**（按可用性探测顺序）：  
   - `Scripting.FileSystemObject` / `ADODB.Stream` 读 utf-8/ansi md、txt  
   - docx：`Documents.Open(ReadOnly)` → 取 `Content.Text` → Close（注意别搅乱当前编辑窗）  
   - 都失败 → UI 提示「请复制到对话」或走 P1 本机桥  
4. **模板**：先接现成 **双轨云 API**（官方 / 我的）；「插入选区」。本机 `模板/` 仅作同步缓存目录，列表可后做。

### P1 — 与扩展对齐体验

1. 扫描 `素材/` 下列表（FSO `GetFolder` 或本机桥）。  
2. 对话/工具环：`read_file` 语义对齐扩展（路径相对工程根）。  
3. 官方包同步到 `模板/`（复用 `officialSync` 思路，由 **本机小服务** 写盘更稳）。

### P2 — 可选本机桥（若纯 JS 读盘不稳）

`127.0.0.1` 上极薄 **local-fs agent**（仅当前用户、仅工程根沙箱）：`list` / `read`。  
侧栏仍只谈「素材/模板」，不暴露任意路径。  
与「稿不上云」一致：桥在本机，不经公网中转存文件。

## 5.1 读 docx / doc，以及「跨文件搜内容」

### 读单个 docx / doc —— **可以，且应后台读、不开标签页**

这是撰写主路径，不是「让用户把素材稿都打开」。

| 格式 | 做法（目标：用户眼前仍只有当前稿） |
|------|------|
| **.docx** | 优先 **不打开排版窗**：当 zip 解 `word/document.xml` 抽纯文本（本机桥或宿主能解压时）；或 `Documents.Open(ReadOnly)` + 尽量不 `Activate` / 读完立刻 `Close`，避免多出标签页 |
| **.doc** | 老格式往往只能走 Open→抽 `Content.Text`→Close；同样要求读完即关、不留标签 |
| **.md / .txt** | FSO/Stream 直接读，最轻 |

实现验收：**读素材过程中，功能区/文档页签不出现那份素材稿**（或仅闪一下可接受则写进已知限制）。

单次撰写只读用户勾选的、或策略限前 N 个/总字数上限，避免一次吞整夹。

### 「随便从哪个文件里搜」—— **不方便，也不建议当主路径**

| 场景 | 是否好做 | 说明 |
|------|----------|------|
| 在**当前打开的稿**里搜 | ✅ 方便 | 现成 `Selection.Find`，校对定位已用 |
| 在**已读入上下文的几份素材**里搜 | ✅ 可做 | 文本已在内存，字符串/简单检索即可 |
| 在**整个素材夹任意文件**里全文检索 | ⚠️ 能做但重 | 要枚举文件 → 逐个 Open 抽文本 → 匹配；慢、抢焦点、易打断编辑 |
| 在**电脑任意路径**随便搜 | ❌ 不做 | 无权限模型、像网盘/桌面搜索，超出产品边界 |

**产品建议（与扩展一致）：**

1. 先 **点选 / @ 素材**（或夹内列表勾选）→ 读进本次会话；  
2. 搜数字、搜原话，优先在 **当前稿 + 已纳入的素材** 里搜；  
3. 「夹内全文检索」若要做，标成高级、限文件类型与数量（例如仅 md/txt/docx，最多扫 N 个），并显示进度——**不要**默认「全盘随便搜」。

## 9. 要不要「左侧面板」？

对标 editor：左工程（素材/模板）+ 右 AI。WPS 里**可以有左侧材料区**，但受本机限制：

| 做法 | 本机 28043 | 建议 |
|------|------------|------|
| 再开一个停靠 TaskPane 贴左 | ❌ 已证实挡正文/卡 Tab | **禁止** |
| **第二个独立窗贴主窗左侧** | ✅ 与右侧助手同套路 | **已定**（真夹正文；两窗跟移见左栏规格） |
| 一个独立窗内左右分栏（左窄：素材/模板；右：撰写精修校对） | ✅ 只维护一个窗 | 备选，本轮不用 |
| 功能区按钮弹出「素材」小窗，用完关 | ✅ | 轻量备选 |

**布局定案**：左工程独立窗 + 右助手独立窗（非 TaskPane）。  
左窗只做列表/勾选/绑定工程，不做完整资源管理器。
