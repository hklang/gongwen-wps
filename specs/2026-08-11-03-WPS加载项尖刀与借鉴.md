### 1.2.1 故障：点「公文尖刀」后正文开头被覆盖、其它 Tab 无响应

**现象（2026-08-11）**：点尖刀相关入口后，文档开始处被顶掉；其它功能区标签失灵。

**高概率原因**：
1. `ribbon.xml` 误写 `getVisible="true"` / `getEnabled="true"`（CustomUI 会把 `"true"` 当**回调函数名**去调，易把功能区搞挂）
2. `CreateTaskPane` 传入**裸文件系统路径**时，部分 WPS 版本会当成「打开/插入该 HTML 到文档」，表现为正文开头被覆盖、界面异常

**已修（须完全退出 WPS 再开）**：
- 去掉错误的 getVisible/getEnabled
- 宿主 `main.js` **禁止**碰 `ActiveDocument`；任务窗格 URL 改为 `file:///.../taskpane.html`
- 若正文已脏：优先 Ctrl+Z；不行则关文件不保存或从备份恢复

**复现仍失败（同日二次）**：点「打开尖刀窗格」后依旧顶掉正文上半、其它 Tab 失灵 → 判定本机 **`CreateTaskPane` + 本地 file 路径不安全**（疑似把 HTML 当文档打开）。

**应急处置（已执行）**：
- `%AppData%\kingsoft\wps\jsaddons\publish.xml` 已**清空插件列表**（尖刀 Tab 应消失）
- 请你：**完全退出 WPS（含托盘）→ 不要保存已污染文档 → 再开**，确认功能区恢复
- 下一版改走 **`ShowDialog`** 或 **`wpsjs debug` 的 http://127.0.0.1`**，禁止再用 CreateTaskPane(file) 直到 http 模式验证通过

### 2.3 借鉴清单（落到我们 MVP）

1. **宿主适配层单独成模块**（对齐 `WpsWordAdapter` / `hosts/wps.js`）：只暴露 `getSelection` / `replaceSelection` / `find` / `highlight` / `listHeadings` / `selectHeadingBody`。  
2. **写回动作表**（对齐察元）：校对用「定位+高亮」；精修用「替换选区」；慎用「全文灌入」。  
3. **工具名稳定**（对齐 xpert `office_word_*`）：侧栏与 relay 工具环可共用语义，即便宿主从 VS Code 换成 WPS。  
4. **安装**：开发期 `wpsjs debug`；交付期 HTTPS `publish.html`；内网备离线包。  
5. **不要**：把 md 工程壳整锅搬进 TaskPane；不要先做四端（表/演/PDF）。
